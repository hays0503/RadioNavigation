# План: родные точки карты для меток мода (drag / ластик / инструменты)

Статус: согласован с автором (2026-11-05), исполняется. Дизайн — «нейтрализованная
родная точка + текущая отрисовка детьми» (вариант 2; вариант «точка = метка»
отклонён как менее надёжный, см. §3).

## 1. Цель

Метки мода на карте (фикс, три вершины LOP, маяки, станции) должны получить
свойства обычных точек карты игры:

- **фикс + вершины LOP** — перетаскивание, удаление (ластик/Delete),
  использование всеми инструментами (Points/Lines/Circles/Angles/Bearing);
- **маяки + станции** — статичные: НЕ перемещаются и НЕ удаляются, но доступны
  всем инструментам, кроме ластика и перемещения;
- **вид остаётся таким, каким был** (иконка, подложка, тултип, деклаттер,
  политика размеров);
- удаление метки — это только удаление метки: расчёты, карточка и проба не
  затрагиваются (метки — результат расчётов, их показ и есть цель).

## 2. Контракт игры (проверено по исходникам)

- `UBOAT.Game.UI.Map.MapPointUI` — обычная точка карты:
  - публично: `Data` (`MapPointData`: `Position` в encounter-пространстве,
    `Name`), `Name` (сеттер включает/выключает label), `Position`,
    `ScenePosition`, `Interactive` (= `image.raycastTarget`), события
    `Changed`/`Destroyed`, `Duplicate(MapPointData)`, статические
    `UpdatePoints(List<MapPointUI>)`, `HoveredPoint`;
  - реализует `IPointerEnter/Exit/Down/Up/ClickHandler`, `ISelectable`;
  - hover: `OnPointerEnter` → `HoveredPoint = this` + каждый кадр
    `gameInput.OverrideHoveredScenePosition(...)` (по этому инструменты и
    «прилипают»); попутно подменяет `image.sprite = hoveredSprite`
    (**приватное поле** `hoveredSprite`);
  - drag: `OnPointerDown` (условие `!gameInput.IsLMBToolEnabled ||
    CurrentTool == Tool.Points`) → в execution-очереди пишет
    `data.Position = SceneToEncounterSpace(gameInput.HoveredScenePosition)`;
  - click: `selectionManager.Select(this)`; при активном инструменте «Точки»
    `MapChartingUI.UpdatePointsTool` открывает **попап переименования**;
  - приватные поля: `image` (Image), `label` (TMP), `hoveredSprite` (Sprite).
- `UBOAT.Game.UI.MapChartingUI`:
  - **публичный** `MapPointUI CreatePoint(Vector2 pos, string name = null)` —
    создаёт из `pointPrefab`, парентит в `linesContainer`, добавляет в свой
    список и в `mapChartingDatabase.AddPoint(data)` → **сохраняется в сейв**;
  - `Tool { Route, Points, Lines, Circles, Angles, Eraser, Bearing }`,
    `CurrentTool`; `gameInput.IsLMBToolEnabled = CurrentTool > Tool.Route`;
  - ластик: `Input.GetMouseButton(0) && MapPointUI.HoveredPoint` → `Destroy`;
  - Delete: `Input.GetKeyDown(KeyCode.Delete) && MapPointUI.HoveredPoint` →
    `Destroy`;
  - `RestoreChartingFromDatabase()` — восстановление точек из базы на
    инициализации карты;
  - `UpdatePoints` (статика, зовётся игрой): `position.y = 1.5 + camY*0.0005`,
    `localScale = camY*0.002` — **позицию и масштаб корня точки игра задаёт
    сама каждый кадр**; вращение не задаёт.
- `MapChartingDatabase`: публичные `AddPoint/RemovePoint`, `Points`
  (`ReadOnlyCollection<MapPointData>`) — точки сохраняются в сейв игры.

Вывод: инструменты/ластик/Delete видят **только** настоящие `MapPointUI`
(через статический `HoveredPoint`) — иного контракта нет. `CreatePoint`
публичный и используется самими инструментами игры → это штатная точка
расширения, не обход.

## 3. Выбранный дизайн и почему

**Вариант 2 (выбран):** на каждую метку создаётся родная `MapPointUI`; её
собственный вид нейтрализуется (невидим, подпись выключена); текущая отрисовка
мода (подложка/иконка/тултип) вешается **детьми** на GameObject точки; свой
компонент-сосед на том же GO ловит события указателя и обслуживает политики.

**Вариант 1 («точка = метка», отклонён):** подложка переезжает в `Image` точки.
Причины отказа (по критериям «не сломается + вид максимально близко»):
- невидимость в варианте 2 — **одно** публичное присвоение
  `image.color = (0,0,0,0)`, устойчивое к любым свопам спрайта и настройкам
  префаба; в варианте 1 надо перекрашивать `sprite/type/preserveAspect/color`,
  завися от неизвестных настроек префаба;
- hover-спрайт игры (приватный `hoveredSprite`) в варианте 1 подменяет
  подложку на наведении → нужен трюк с порядком компонентов; в варианте 2
  он невидим по определению;
- подложка не может лежать *под* иконкой (дети всегда рисуются поверх
  родителя) → в варианте 1 пришлось бы собирать подложку и иконку в один
  спрайт; в варианте 2 порядок родной;
- функционал (drag/ластик/инструменты) даёт сама точка, а не её `Image` —
  вариант 1 не даёт ничего сверх.

«Невидимый якорь» — не новый приём: в текущем коде мода уже есть невидимый
`Hitbox` (прозрачная `Image` с `raycastTarget=true`); мы заменяем его родной
точкой.

## 5. Политики (таблица)

| | фикс + LOP | маяки + станции |
|---|---|---|
| Существование | по состоянию: фикс есть и не Suppressed → точка есть | всегда (по реестру профилей/станций) |
| Перемещение | родное (drag двигает `data.Position`) | **заблокировано**: LateUpdate возвращает истинную позицию |
| Удаление ластиком | родное (Destroy) | **заблокировано**: при `CurrentTool == Eraser` → `Interactive=false` |
| Delete (клавиша) | родное | страховка: `Destroyed` → реконсиляция пересоздаёт |
| Инструменты | все | все (кроме ластика и перемещения) |
| Инструмент «Точки» активен | `Interactive=false` (иначе попап переименования и ренейм ломают адопцию) | то же |
| После удаления | подавление до нового наблюдения (I) / сброса серии (O); расчёты/карточка/проба не трогаются | — |

Имя метки (`Data.Name`) — ключ адопции: `RadioNav FIX`, `RadioNav LOP B+C`,
`RadioNav LH <id>`, `RadioNav STN <id>`; мод пере-утверждает его (сравнение
перед записью), label выключен (`label.enabled = false` — иммунно к
`SetActive(true)` из сеттера `Name`).

## 6. Жизненный цикл и реконсиляция (state-driven, самовосстанавливающаяся)

1. **Желаемый набор** считается из состояния мода (фикс/LOP — из worksheet,
   маяки/станции — из реестров) с учётом `Suppressed`.
2. **Реконсиляция** (по событиям: открытие карты, смена состояния, публикация
   фикса; плюс редкий периодический проход, не каждый кадр):
   - для каждого желаемого ключа: найти существующую точку по имени
     (скан `FindObjectsOfType<MapPointUI>()`) → адоптировать + «одеть»
     (нейтрализация + дети + мост), иначе создать через `CreatePoint` и одеть;
   - точки мода, которых нет в желаемом наборе (устаревшие, дубли, сироты
     после ренейма) → `Destroy`;
   - статичные, уничтоженные клавишей Delete → пересоздать (страховка).
3. **Каждый кадр (LateUpdate моста, порядок после игры):** компенсация
   масштаба детей (политика `LighthouseMarkerSizing`), ориентация
   (`Euler(90,0,0)`), локальный подъём (`+SpriteLiftY`), для статичных —
   возврат `Position` при расхождении, сравнение/пере-утверждение имени,
   проверка `label.enabled`.
4. **Деклаттер маяков** (существующий `MarkerDeclutter`): скрытым — активность
   GO точки + `Interactive=false`; пин/ховер не подавляются (как сейчас).
5. **Сейв**: точки сохраняет игра (как обычные); при загрузке реконсиляция
   адоптирует их, а не плодит дубли.

## 10. Риски и закрытие

| Риск | Закрытие |
|---|---|
| Неизвестная иерархия префаба (где Image/TMP, ротация) | Шаг 0 (живая инспекция) до кода |
| `alphaHitTestMinimumThreshold` > 0 → прозрачная точка не ловит курсор | ставим `0` (публично) + живая проверка hover |
| Слой сортировки: иконки переезжают из слоя маркеров сущностей в чарт-слой | A/B скриншот; при необходимости вложенный `Canvas` + `overrideSorting` на визуале |
| Подъём/ориентация: игра задаёт позицию/масштаб корня, но не подъём/вращение | локальная компенсация детей (`+SpriteLiftY`, `Euler(90,0,0)`) в LateUpdate |
| Реконсиляция каждый кадр (дорогой скан) | сканы по событиям + редкий периодический проход; per-frame только дешёвые коррекции |
| Ренейм через инструмент «Точки» ломает адопцию | `Interactive=false` при активном «Точках» + пере-утверждение имени |
| Дубли после загрузки (игра восстановила + мод создал) | адопция по префиксу в реконсиляции; лишние — `Destroy` |
| 209 точек маяков: производительность/сейв | точки в одной канве игры (не хуже текущих 209 канв); сейв ~15 КБ; живая проверка FPS |

## 12. Отложено

- Фазирование (Ф1 фикс/LOP → Ф2 маяки/станции) — решением автора отложено,
  делаем одним заходом.
- Персистентное «удалить маяк навсегда» (список в PlayerPrefs) — не делаем;
  статичные не удаляются по определению.
- Линии LOP дугами (сейчас — точки-вершины) — вне объёма.
- Отдельный `inConeNow` для пробы (N5 прошлого раунда) — вне объёма.
