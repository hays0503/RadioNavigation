# Игровой лаг и географический перенос ЛП — разные метрики

Проверено14.10.2026; не приватное чтение позиции/скорости конкретной лодки.

- `Coordinates.cs:37–59`: encounter-км вφ/λ переводятся линейно одинаковым
  коэффициентом360/40075,16. Широтной поправки для восточной оси нет.
- `Sandbox.cs:988–1001`: scene-метры ×0,001 + origin → encounter-км.
- `SandboxPlayerWolfpack.cs:1515–1518`: положение лодки использует именно эту
  цепочку. Travel/snap/region-сдвиги существуют отдельно; не считать их нулём
  без проверки сценария.
- `ShipControlUI.cs:1303–1306`: скорость сцены, а не масштабированная по
  параллели географическая скорость. При scale>100 меняется тип scalar,
  см. `navigation-instrument-contracts.md`.

Для1,852км сцены изменение каждой координаты≈0,998204′. Поэтому в
географической сетке наφ55° (FulstT13:1NM=1,74′λ) игровая восточная
компонента пути должна быть умножена на0,998204/1,74≈0,573681,
северная — на0,998204. Не применяйте это к уже географическому пути повторно.
На другой расчётной широте нужна другая клетка T13, не фиксированный0,573681.

Непосредственное нанесение игровыхV×GMT в равномасштабную географическую
E/N-сетку смешивает метрики. Это объясняет, почему неподвижная ЛП может
сходиться, а старые перенесённые — систематически уходить по долготе.
