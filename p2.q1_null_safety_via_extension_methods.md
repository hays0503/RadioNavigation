# P1.Q1_NullSafetyViaExtensionMethods (.IsNull/.IsNotNull/.IsZero)

**Приоритет:** P1-Major  
**Архитектурная область:** Logic / Data — безопасное обращение с данными  
**Статус:** Не задокументировано, нужно создать файл  

---

## Описание проблемы

В проекте повсеместно используются extension-методы `.IsNull()`, `.IsNotNull()`, `.IsZero()`, `.IsPositive()`, `.Negligible()`, `.IsNegative()` — вероятно из `ComparisonExtensions`. Это создаёт ложное чувство безопасности: методы скрывают реальные null-reference исключения и затрудняют статический анализ (Roslyn/SonarQube видят условные выражения как "проверки null", но не распознают pattern-и).

**Находится в:**
- `Source/Logic/ComparisonExtensions.cs` — определение методов
- dozens of call sites across UI / Logic — вызовы `.IsNull()`, `.IsNotNull()`

## Технический анализ

1. **Extension methods on reference types.** `IsNull(this object obj)` — удобно, но Roslyn nullability analysis не видит эти методы. Static analysis tools report zero findings for NRE risks even where real ones exist.
2. **Nullable context unawareness.** Project targets .NET Standard 2.0 which predates nullable reference types (C# 8). Extension method wrapper doesn't help migrate to `<Nullable>enable</Nullable>` later — code must be manually audited.
3. **False confidence in safety.** Call sites like `if (measurements.IsNull()` look protective but the extension might just return `obj == null`, which is fine, yet developers stop writing explicit defensive checks elsewhere because they "trust" this pattern.

## Примеры из кода

```csharp
// Source/Logic/PositionFixCalculator.cs:27
if (measurements.IsNull() || measurements.Count < 2)
    return new FixResult { Valid = false };

// Source/Sound/AudioSynthesisEngine.cs:110  
if (seq.IsNull() || seq.ElementCount.IsZero())

// Source/UI/InformationPanelHandler.cs:163
if (toggleHandler.IsNull()) Debug.LogError(...)
```

## Риски

| Риск | Уровень | Описание |
|------|---------|----------|
| False positive of null safety | Medium | Static analyzers cannot see through extension methods |
| Migration path to nullable contexts blocked | High | Cannot migrate to C# 8+ `<Nullable>enable</Nullable>` without auditing every site |
| Masked NRE bugs | Medium | If extension itself has a bug or is overridden, null checks silently pass |

## Рекомендуемое решение

1. **Перейти на C# nullable reference types:** `<Nullable>enable</Nullable>` в `.csproj` для всех новых файлов.
2. **Поэтапный отказ от `.IsNull()`/`.IsNotNull()`:** заменить на `is null` и `is not null` — это встроенные языковые конструкции, которые Roslyn-анализаторы понимают корректно.
3. **Сохранить `.IsZero()` как utility:** проверка `== 0` тоже OK, но extension-обёртка стоит того (проверяет float-eps).

## Файлы для изменения

| Файл | Кол-во совпадений | Действие |
|------|-------------------|----------|
| ComparisonExtensions.cs | — | Сохранить `IsZero()`, удалить/депрецировать `IsNull()` |
| PositionFixCalculator.cs | 3+ | Заменить на `if (measurements == null || measurements.Count < 2)` |
| AudioSynthesisEngine.cs | 5+ | Аналогично |
| All UI handlers | ~15 | Перевести `.IsNull()` → `== null`, `.IsNotNull()` → `!= null` |
