# ComparisonExtensions Anti-Pattern — Obscures Idiomatic C# Code

## Problem

Codebase uses custom extension methods like `.IsNull()`, `.IsNotNull()`, `.IsPositive()`, `.IsNegative()` instead of native C# operators:

```csharp
// Instead of idiomatic C#:
if (obj == null) { }           // idiomatic ✓
if (freq > 0f) { }              // clear & concise ✓

// We see non-idiomatic patterns:
if(obj.IsNull()){ }            // less readable to experienced devs ✗ 
if(freq.IsPositive()){ }       // no clearer than f > 0f ✗
```

Worse, `.IsZero(0)` returns true for `== 0`, not approximate float comparison. The method name "IsZero" suggests exact comparison but at line 56 of InformationPanelHandler it compares against another potentially imprecise value. This is confusing naming.

## Impact
- Makes code harder to read for any experienced C# developer — looks like Java-style defensive coding in a C# project
- Nullable reference types (when enabled) and pattern matching would be far more idiomatic

Additionally the entire project has nullable reference warnings suppressed in `.csproj` line 10, which masks potential null deref risks that these extension methods were probably introduced as a workaround for. This creates a vicious cycle: suppress warnings → use extension methods → code stays unidiomatic → warnings still suppressed.

## Recommended Fix
1. Replace all `.IsNull()` with `== null`, `.IsNotNull()` with `!= null`  
2. Replace `.IsPositive()`, `.IsNegative()` with native comparisons `> 0f`, `< 0f`
3. Consider enabling nullable reference types (remove CS86xx warnings from NoWarn) and using `?.` operator pattern matching
