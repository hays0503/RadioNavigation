## Описание проблемы

`PositionFixCalculator` из 224 строк в single static class объединяет **~6 ответственностей** на разных уровнях абстракции, несмотря на имя "calculator":

| # | Ответственность | Строки | Детали |
|---|---------------|--------|--------|
| 1 | Data struct для входных измерений (DTO) | 8-15 | `public struct Measurement` — entity model вложенной в algorithm code |  
| 2 | Data struct для результатов (DTO) | 17-23 | `public struct FixResult` — ещё один DTO возвращаемый caller'у |
| 3 | Intermediate calculation types: GeoPoint + WeightedPoint | 121-133 | Два additional implementation detail leak into class scope как unrelated к PositionFix types |  
| 4 | Core algorithm: bipartite intersection + weighted centroid | 25-119 (~95 LOC) | Двойной O(n²) nested loop finding intersections между all beacon pairs; first pass raw intersections (строки 32-44); second weighted loop (строки 69-89) |
| 5 | **MUTATION HAZARD — in-place mutation of caller's data** | строка 64 | `measurements[i] = m` модифицирует input list caller'а в place как hidden side-effect. Это BUG potential если caller reuse original data позже! |
| 6 | Spherical geodesy intersection math (FindIntersection) | 135-200 (~67 LOC) | Full triangulation с bearing computation — ~67 LOC trig-heavy code который better standalone utility или GeoMath class. Включает: distance calc (Haversine), forward/ backward azimuths angles, point-at-distance formula |  
| 7 | Utility function `GetDistanceKM` Haversine) | строки 203-217 | Buried alongside navigation-specific positional math даже though это general-purpose geo-function usable везде else в проекте |

**Архитектурная проблема:** класс чьё имя не описывает его actual responsibilities — он больше "PositionFixCalculator + GeoUtils + MeasurementTypeDeclarations".

## Таблица рисков

| Риск | Вероятность | Влияние | 
|------|-----------|--------|-----|
| Measurement/WeightedPoint should be separate public types для serialization/UI consumption | Средняя | Сейчас opaque к callers, unable to inspect intermediates или дебажить step-by-step |  
| FindIntersection too complex (WLOC ~70) — hard unit-test без mock-bearing данных | Высокая | Math errors go undetected потому что method не тестируемый изолированно от PositionFixCalculator 
| O(n²) scaling measurement count растёт linearly при добавлении beacons к 14 max station now acceptable dangerous if more added later | Низкая-Средняя | Current 14 stations = C(14,2)=91 pairs x2 passes ≈ 180 total ops — OK for now |

## Рекомендованное решение — extraction и decomposition

Extract into **`Source/Logic/GeoMath.cs`** (new file):
- `FindIntersection()` → standalone utility function accepting lat/lon/brng arguments + returning GeoPoint
- `GetDistanceKm()` stays as-is или rename к `ComputeHaversineDistance`  
- `ToRadians()` helper метод move туда же

Extract Data Structures:
- GeoPoint → separate file (`GeoPoint.cs`) для intermediate calculation types
- WeightedPoint → private to GeoMath (не нужен outside)
-Measurement и FixResult stay public в их own files или как standalone DTOs, но лучше вне PositionFixCalculator

Keep `PositionFixCalculator` thin orchestration: input validation → call FindIntersection pairwise → collect results → weighted centroid → average. Reduce LOC до ~50 строк focused на navigation logic only.
