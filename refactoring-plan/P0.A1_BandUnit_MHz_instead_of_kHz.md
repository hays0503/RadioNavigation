# Band Unit Error — MHz Displayed Instead of kHz

## Problem

`DialConfig.Bands[0]` (Band I) defines frequency range as `RangeMin = 70, RangeMax = 150` with `Unit = "MHz"`. However, historical CONSOL/Sonne beacons operated in the VLF band (~30-80 kHz), not MHz. The unit label is off by three orders of magnitude.

When a user tunes to Band I and reads the frequency display:
```csharp
// DialConfig.cs line 153 — formatFrequency format string
band.Unit + "'" → displays "70.0 MHz" instead of "98.5 kHz"
```

### Affected Bands

| Band | RangeMin | RangeMax | Unit (current) | Likely True Unit |
|------|----------|----------|----------------|------------------|
| I    | 70       | 150      | MHz ❌        | kHz              |
| II   | 150      | 340      | kHz            | ? (verify)     |
| III  | 340      | 866      | kHz            | Likely correct   |
| IV   | 720      | 3500     | kHz            | Likely correct       |

## Impact
- User sees wrong frequency units — **tune completely off-frequency** if they use real equipment or reference tables
- Misleading display breaks immersion and usability for a radionavigation game
- Potential for silent incorrect calculations if frequency values are compared against thresholds assuming kHz vs MHz

## Recommended Fix

1. Change `Unit = "MHz"` to `Unit = "kHz"` for Band I in DialConfig.Bands[0] at line 64
2. Historical verification needed: confirm CONSOL/Sonne beacon frequency bands historically (30-80 kHz is standard VLF)
3. Update all display formatting code that uses this unit value — any conversion logic assuming MHz will break if not updated

## Verification
- Test game UI with Band I tuned → should show "70.0 kHz" through "150.0 kHz
- Compare displayed values against real CONSOL beacon frequency tables online
- Any other place where dialConfig.Unit used for display/formatting — verify still appropriate

## Historical Context

CONSOL/Sonne direction-finding equipment operates in the VLF band (30-80 kHz), which is consistent with Band 1 settings and Range [70, 150] kHz. This needs to be verified by historical references before finalizing this fix. If incorrect on a broader scale — e.g., multiple bands need MHz unit corrections — then all 5 bands should be cross-referenced before making any changes.)
