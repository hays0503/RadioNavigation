# Debug.Log in audio callback path

## Problem

`Debug.Log()` calls inside `AudioSynthesisEngine.ProcessAudio()` fire on every phase transition for each station — potentially thousands of times per frame at the ~44 kHz sample rate. Unity's Debug.Log is expensive due to interop synchronization, C-strings, and internal buffering. Calling it from audio processing callback adds CPU overhead and thread contention with the main game thread.

Same pattern elsewhere:
- `ZoneHandler.cs:62/78` — logs every left/right click during gameplay
- `InformationPanelHandler.cs:421:` — logs decoded signal text multiple times per second when decoded text is non-empty

Excessive logging in audio code will cause performance issues and fill up the log output with noise, making it nearly impossible to diagnose real problems.

## Impact
Crackling or dropout in audio playback under high CPU load player's system due to thread contention between debug-log sync mechanism and sample processing loop.
"Log spamming the entire console even normal play session (44k / 100ms = 440 samples worth of debug logs per frame if every phase transitions triggers).

## Recommendation Fix
1. Remove ALL `Debug.Log(` calls from AudioSynthesisEngine.cs entirely or gate behind dedicated feature-flag only for debugging specific issues (`[Conditional("DEBUG")]`)
2. Same for all other Debug.Log in UI/ interaction paths unless gated behind an actual user-configurable debug toggle (not always-on)

```csharp
public static class RadioDebugLogger {
    [System.Diagnostics.Conditional("DEBUG_RADIO_NAV")]
    public static void Log(string msg) => UnityEngine.Debug.Log("[RadioNav] " + msg);
}
```

Verify Debug logs no longer appear in audio callback by checking Unity Profiler.
