# SonneController is a God Object — Must Decompose

## Problem

SonneController contains **7+ distinct responsibilities**:
1. Audio engine coordination (`audioEngine = new AudioSynthesisEngine()`) at line 44
2-92: Station lifecycle management (initializes, subscribes ALL 14 beacons' keyers/schedulers/carriers)
3. Signal decoding logic (DecodeCallsignBuffer with custom Morse string matching) lines 170->212 
4. Position fixing orchestration (UpdateStationGains + UpdateStationNavigation calls PositionFixCalculator) at 337-441  
5. Bearing calculations (NormalizeAngle from scratch compute bearing) at 481-506 (also duplicated in PositionFixCalculator — see M9)
6. Static diagnostics API for UI consumption exposed as GetDiagnosticInfo() at lines 263->305
7. Unity lifecycle hooks ( Awake/OnDestroy Update) onlines `Awake`, `OnDestroy`,`Update` lines 44,112 320

At 508 total LOC with 30+ methods and 25+ fields — **this class simply cannot be maintained or tested in isolation**. Every change to noise floor affects bearing math code mentally. The class also has tight coupling (it instantiates AudioEngine inside its own field, initializes station lists itself, manages multiple MonoBehaviours subscriptions internally, etc.)

## Recommended Decomposition

Extract these 4-5 separate classes:
1. **`StationAudioCoordinator.cs`** — coordinate with audio engine; handles BeatFrequency & CarrierGenerator setup per-station
2. **`SignalDecoder.cs`** — DecodeCallsignBuffer + Morse signal processing lines 170->212
3. **`BeaconNavigationManager.cs`** — bearing/calculation normalization logic; also manages navigation cycle logic updateStationGains pattern)
4. **`PositionFixOrchestrator.cs`** — wraps PositionFixCalculator calls & handles result delivery → UI

## Verification

- Each extracted class should have its own unit-test coverage (>80% branch conditions for business logic). No test that requires full Unity scene to execute. 
- SonnenController lines drop below ~200 LOC after extract)
- Existing navigation behavior unchanged before/after refactor (integration tests if they ever get added.)
