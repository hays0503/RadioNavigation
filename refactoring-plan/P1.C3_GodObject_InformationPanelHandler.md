# InformationPanelHandler is a God Object — Must Extract Concerns

## Problem

This MonoBehaviour handles **5+ distinct responsibilities**:
1. Programmatic UI creation — factory method (`CreateLabel()`, `CreateSeparator()` 12 calls hardcoded paths) at lines 39-80, Layout management (VerticalLayoutGroup + ContentSizeFitter at runtime) at lines 99->119
2. Handler discovery — seven `GetComponentInChildren` calls with repeated null-error logging find children) at 153->170
3. Event subscription/unsubscription boilerplate — seven event registrations in one method, mirrored unsubscribe) at 172-202 (plus `OnDestroy()`) 
4. Display update logic for **four different information streams** (patterns, signals decoded text position fix), each with color/formatting rules) UpdatePatterns(), UpdateFixDisplay(), UpdateSignalDisplay()) lines 83-97
5. Signal processing business logic — Gaussian weighting function (`FindClosestStation` with Gaussian decay formula at line 433) should be in a service layer not UI.

This single class has more "life" than an entire game screen controller. Extract the UI factory into `PanelLayoutBuilder`, handler discovery logic separately, and separate display-update concerns if they ever add logic later.

## Additional Concerns

- Event subscription boilerplate is extremely redundant — each registered/unregistered event pair should be declarative rather than imperative
- FindClosestStation business logic contains Gaussian decay formula that belongs in the service/game layer, not inside a UI component
- Directly queries game state via `transform.Find()` (line -222, 230)-creating tight coupling to specific prefab layout

**474 lines — this class is tightly coupled to the game codebase's exact scene graph layout of that makes every single one of its own methods hard to test in isolation.**

## Recommended Fix
1. Extract factory/layout creation logic into `PanelLayoutBuilder` (create all labels, separators layout groups) 
2. Move business-logic (`FindClosestStation`) — it should go into separate class/service layer `NavigationService` or similar interface. UI calls this service not implements
3. Replace imperative seven-subscription-block with declarative subscription model

## Verification
- Extracted classes don't need Unity scene for unit-tests (pure POCO/PORC tests)
- All existing UI behaviour remains identical when UI is opened/closed
