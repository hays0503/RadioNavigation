# P2.Q5_DuplicateConstants_BfoBase_MinMax

**Приоритет:** P2-Minor  
**Область:** Code Smell / DRY Violation, Magic Numbers  
**Статус:** Новый документ  

---

## Описание проблемы

Оба `SonneController.cs` и `AudioSynthesisEngine.cs` имеют идентичные константы с одинаковым именем и значением: `BfoBase = 1000f`. Это real-world параметр смещения heterodyne mixer для симуляции Sonne приёмника (IF beat frequency):

```csharp
// SonneController.cs строка 12: 
private const float BfoBase = 1000f;

// AudioSynthesisEngine.cs строка 9:  
private const float BfoBase = 1000f;
```

Каждый private в своём классе, скрывая duplication от стандартных grep-поисков по символу. Оба используются для вычисления beat frequencies (в Hz) относительно центра полосы пропускания receiver band:

```csharp
// SonneController.cs строка 81 (при andнициализации station):
BeatFrequency = BfoBase,  // устанавливает начальный IF baseline на 1000 Hz 

// SonneController.cs строка 369 (computed beat frequency с offset):
stations[i].BeatFrequency = Math.Max(300f, Math.Min(1800f, BfoBase + offset * 1000f));

// AudioSynthesisEngine.cs строка 59 (frequency offset для tuning display):
float offset = currentFrequencyKHz - (stations[i].BeatFrequency - BfoBase) / 1000f;
```

`BfoMin` (300f) и `BfoMax` (1800f) определены только в `AudioSynthesisEngine.cs` на строках 10-11 — но они также инлайн использованы (без констант!) в SonneController:строка 369 через прямые Math.Max/Min вызовы с literal значениями. Эта инконсистентия усугубляется: иногда constants реиспользуются корректно, sometimes hardcoded literals дублируются.

## Почему это проблема (сценарий расхождения)

```
Сценарий spec изменения или документация proves что Sonne equipment использует 1200 Hz instead of 1000 Hz как IF offset:

dev открывает AudioSynthesisEngine строка 9 меняет на =1200f → компилируется, audio path корректна ✓
тот же dev открывает SonneController и НЕ видит BfoBase в ЭТОМ файле (diff показывает изменение только в другом месте) → forgets to update строку 12 → BeatFrequency offset off by 200 Hz для gain calculations на дисплее → subtle bug без очевидного warning sign.
```

## Таблица рисков

| Риск | Вероятность | Влияние | Комментарий |
|------|-----------|--------|-------------|
| Values eventually diverge as код evolves independently | Высокая со временем | Средняя — wrong beat frequencies в simulation output (audio drifts from displayed tuning) | Оба private поэтому change одного не вызывает compile errors на caller site другого |

## Рекомендованное решение: central constants file

Создать `Source/Data/SonneAudioConstants.cs`:

```csharp
namespace UBOAT.Mods.RadioNavigation
{
    /// <summary>Static constants for Sonne receiver audio simulation parameters</summary>
    public static class SonneAudioConstants
    {
        /// <summary>Intermediate frequency beat offset for heterodyne mixer (1000 Hz IF)</summary>
        public const float BfoBaseHz = 1000f;

        /// <summary>Minimum allowable beat frequency clamp — lower bound of receiver passband (300 Hz)</summary>
        public const float BfoMinHz = 300f;

        /// <summary>Maximum allowable beat frequency clamp — upper bound of receiver passband (1800 Hz)</summary>
        public const float BfoMaxHz = 1800f;

        /// <summary>Standard sample rate for Sonne audio synthesis</summary>
        public const int SampleRate = 44100;
    }
}
```

Заменить оба private определения + inline literals в SonneController на shared reference `SonneAudioConstants.BfoBaseHz`.
