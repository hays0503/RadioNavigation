# P1.Q10_EventSubscriptionLeaks_StaticEventsNoUnsubscribe

**Приоритет:** P1-Major  
**Область:** UI — event memory management (GC leaks)  
**Статус:** Новый документ  

---

## Описание проблемы

`RadioHandler.cs:9-11` объявляет **static events** которые подписываются через Unity lifecycle но никогда явно unsubscribe — это создаёт potential **memory leak / stale reference leak** когда объекты должны быть garbage collected после смены сцены или reload mod'а.

```csharp
// RadioHandler.cs строки 9-11  
public static event Action<bool> OnVisibilityChanged;
public static event Action<float, int> OnFrequencyChanged;
public static event Action<float> OnCursorAngleChanged;

// SonneController.cs строка 48: подписка на static event
void Awake() {
    RadioHandler.OnFrequencyChanged += OnFrequencyChanged; // ← never unsubscribed!  
}
```

### Анализ проблемы

Когда `RadioHandler.Instance` (static singleton reference) или `SonneController` GameObjects destroyed при смене сцены — **static events сохраняют ссылки** на подписавшиеся объекты. Если они не отписываются явно (`-= `, то GC не сможет собрать stale subscribers forever пока app live.

Это особенно опасно в Unity при:
1. **Mod reload** без full restart —旧 SonnenController instance может оставаться alive с dead references  
2. **Scene transitions** где old scene objects подписаны на static events но никогда не отписываются
3. **Editor testing rapid cycle** — каждый play-mode session accumulates stale subscribers

## Кодовые примеры проблемы

```csharp
// RadioHandler.cs:9 — Static event declaration  
public static event Action<float, int> OnFrequencyChanged;

// SonneController.cs:48 — Subscribes but NEVER unsubscribes!
void Awake() {
    RadioHandler.OnFrequencyChanged += OnFrequencyChanged;  // ← no -= anywhere in file!  
}

// InformationPanelHandler.cs ~10 places subscribe to static events without unsubscribe at Destroy/OnDisable time.
```

Строки `RadioStoryIntegration` line 149 и строки RadioStoryIntegration.Destroy() не содержат any explicit `UnsubscribeAll()` или `+= null cleanup`.

## Риски GC leaks

| Риск | Вероятность | Влияние | 
|------|-----------|--------|-----
| Stale subscribers prevent garbage collection of destroyed objects | Высокий (без unsubscribe в Destroy()/OnDestroy()) | Memory accumulates across scene transitions — potential OutOfMemory при длительных сессиях или multiple reloads 
Static events hold strong references to instance references → prevents collecting even if no external reference exists | Постоянная (architectural design)

## Рекомендованное решение

1. **Add IDisposable pattern + weak events для Unity MonoBehaviours:**
   ```csharp  
   // SonneController.cs — add explicit Unsubscribe()
   void OnDestroy() {
       RadioHandler.OnFrequencyChanged -= OnFrequencyChanged;
       // unsubscribe all other static listeners here 
   }
   ```

2. **Implement proper listener registration/unregistration pattern:**
   Create `ISoundListener` interface that handles subscribe at Awake, unsubscribe at OnDestroy автоматически с помощью Unity lifecycle hooks.

3. **Или использовать WeakEventListener wrapper** который не блокирует GC от collection subscriber objects:
   ```csharp  
   // Generic weak event pattern that doesn't prevent garbage collection of subscribers
    public class WeakActionListener { 
        private readonly Action<float, int> _action; 
        
        public WeakActionListener(Action<float, int> action) => _action = action;        
   
        internal void Invoke() { 
            var target = _action.Target; // will become null when GC'd
            if (target != null) _action.Invoke();  
        }    
    }
   ```

4. **Add cleanup handler в Main.cs OnSceneChange:** iterate all subscribers and force-unsubscribe them when scene changes explicitly.
