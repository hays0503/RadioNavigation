## Описание проблемы

`RadioStoryIntegration` — это статический класс из 381 строки, объединяющий **6 независимых ответственностей** на уровне домена игры:

| # | Ответственность | Строки | Описание |
|---|---------------|--------|----------|
| 1 | Логи версия Unity/игры | 53-54 | `Application.version` — отдельно от reflection setup | 
| 2 | Reflection-интроспекция RadioStory | 56-107 | Поиск InsertDecision, конструкторов Decision, кэширование stageField/decisionsProp/onUpdatedMethod/languageProp — все в одномInit() ~60 LOC |
| 3 | Вставка решения в игровой сюжет | 109-148 | Создание объектов через reflection, in sertion в RadioStory.Decisions list, вызов OnUpdated для UI-обновления | 
| 4 | Переопределение локализованных строк | 264-293 | OverrideLocaleKey() + Dictionary с "russian" → русский лейбл для меню игры |
| 5 | Обработка кастомных решений (два разных поведения) | 334-373 | HandleCustomDecisions: toggle радио (строки 354-357) И скрытие панели при Leave Station (строки 346-351) — два действия один метод не может разнести | 
| 6 | Управление кэшем рефлекшн-состояния между сценами | 27-38 | ResetRuntimeState стирает весь кэш одновременно

## Почему это проблема

1. **Огромная точка отказа.** При обновлении UBOAT, класс тихо падает на любом этапе между строкой 56-107 когда introspection код бросает NullReferenceException — caught by various `try/catch` blocks и мод **работает в сломанном состоянии без уведомлений пользователя**.
2. **Скрытое копирование кода.** One exact ScriptableObjectSingleton → Locale resolving block (строки 297-305) копируется повторно в GetCurrentLanguage() (строки 314-324). Если сборка или неймспейс игры изменится — разработчик должен обновить оба места вручную.
3. **Невозможность юнит-тестирования.** Каждый публичный метод требует RadioStory instance либо Unity scene context. Невозможно протестировать DecisionInjector или LocaleOverrideHandler отдельно.

## Таблица рисков

| Риск | Вероятность | Влияние | Комментарий |
|------|-----------|--------|-------------|
| Reflection target renamed/removed новым UBOAT update | Высокая | Полный отказ мода — тихая failure, видна только в логах как "Init failed" | Нет compile-time guard'ов против переименованных методов. Каждое обновление игры = риск |  
| Непоследовательный кэш после смены сцен | Средняя/Высокая | В меню появляются неверные решения или панель остаётся видимой после окончания сюжета | ResetRuntimeState must быть вызван правильно Main.cs при каждой смене сцены |
| Поглощение ошибок мешает debugging | Средняя | Пользователь не понимает какое из 9+ возможных падений вызвало проблему — только "InjectT3PLL38Decision error" в логе |

## Рекомендованное решение — декомпозиция на 4 класса

1. **`RadioStoryReflectionService.cs`** — единственный Init(), version detection, кэширование всех reflection результатов (типы, поля, конструкторы, методы). Методы возвращают bool success/failure, callers не дублируют null-check logic
2. **`DecisionInjector.cs`** — принимает ReflectionService как dependency, создаёт решения через cached constructors, вставляет на правильный индекс. Каждый вызов имеет изолированный try/catch  
3. **`LocaleOverrideHandler.cs`** — standalone dictionary-based service для string key → localized label маппинга
4. **`DecisionDispatcher.cs`** — HandleCustomDecisions logic перенесён сюда отдельно
