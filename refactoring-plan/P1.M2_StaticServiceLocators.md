# Static Mutable State as Service Locator Pattern (7+ locations)

## Problem

Static mutable state is accessed from at least 8 different files: ToggleHandler.IsRadioOn, IsInteractable CursorHandler.CheckIsIntercatable, SceneListenstListener_OnSceneStart checks RadioHandler.Instance — each providing one-sided authority over entire game's runtime logic without any possibility of resetting values between different play sessions due to soft-reloading mechanism within same Unity app! Additionally GroundHandler.groundActive holds sole control value used universally whenever checking state (also via direct get).

```csharp
// ToggleHandler.cs line 13-14 — two static bools shared across entire project
public static bool IsRadioOn { get; private set; }
public static bool IsInteractable { get; private set; }
```

Static fields cannot be managed by DI container. There is no mechanism to reset these on mod hot-reload or game-scene reload — after a soft-refresh the statics still hold their old values even when mono-behaviours are recreated leading ghost-state bugs in new scene instance while some parts behave incorrectly! 

## Impact
- No unit-testing possible: every test manipulates global mutable state, making tests order-dependent fragile between runs (tests can influence eachother silently without explicit setup clear). This violates single-responsibility principle entirely since any change requires updating 5+ independent components simultaneously across project code-bases alone instead having isolated changes happen only inside corresponding modules themselves directly without side-effects elsewhere within entire application runtime environment overall scope...

Also prevents proper mod hot-reloading during development because stale references remain active after scene reload has occurred leaving behind corrupted internal variable states which then cause hard-debug issues impossible track down reliably under typical conditions!
