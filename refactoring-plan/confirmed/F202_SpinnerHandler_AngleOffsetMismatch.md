## Описание

В `SpinnerHandlerBase.OnDrag` целевой угол вычисляется с добавкой 90°, а визуальная ротация применяется без неё:

```csharp
// SpinnerHandlerBase.cs:26
protected virtual float GetAngleOffset() => 90f;

// SpinnerHandlerBase.cs:90-98
float angle = Mathf.Atan2(dir.x, dir.y) * Mathf.Rad2Deg + GetAngleOffset(); // value = β + 90
float targetAngle = ClampTargetAngle(angle);                                 // clamp [min, max]
currentAngle = Mathf.Lerp(currentAngle, targetAngle, sensitivity);
spinnerRect.localRotation = Quaternion.Euler(0, 0, -currentAngle);           // visual = -value
```

Сопоставим с эталонной реализацией `CursorHandler.OnDrag` (`CursorHandler.cs:69-73`), где **offset отсутствует**, а ротация стрелки `-angle` при направлении указателя `Atan2(dir.x, dir.y)` даёт точное следование стрелки за курсором (направление стрелки `(-sin(-a), cos(-a))` ≡ нормализованный вектор указателя).

Для спиннера с тем же визуальным контрактом («ручка указывает на указатель») требуется `visual = -value + 90°`, либо `value = Atan2(dir.x, dir.y)` без offset. В коде одна из двух половин сопоставления сломана на ровно те же 90°:

### Следствия (при ручке, указывающей вверх в локальном пространстве)

1. **Прыжок значения при захвате.** Угол ручки на экране = CW-угол от «вверх» = `value`. Курсор на конце ручки имеет угол указателя `β = value` → новое значение `value + 90` → скачок на 90° из 140° диапазона (**~64% шкалы**). Захват ручки в 0% → значение уползает к ~64% без движения мыши.
2. **Мёртвая зона.** `HandleDragDirection` (`SpinnerHandlerBase.cs:29-34`) отклоняет драг при `dir.y < 0`: ручка в положении `value > 90°` направлена ниже горизонтали → захват игнорируется. Нижняя половина шкалы физически недостижима прямым захватом ручки.
3. **Уменьшение значения затруднено.** Из максимума (140°) единственный путь вниз — захват выше горизонтали в обход ручки (значение всё равно не совпадёт с позицией курсора).

> **Оговорка:** точная ориентация графики ручки задана в бинарном AssetBundle (`Bundles/testui`), из исходников недоступна. При ручке, направленной влево (9 часов) в локальном пространстве, приведённая математика самосогласована (прыжок исчезает), но тогда бессмысленен сам паттерн `-currentAngle` и проверка `dir.y < 0` (никогда не срабатывает). В любом варианте между `+90` в значении и `-value` без компенсации в визуале существует объективное противоречие, которого нет в `CursorHandler`.

## Влияние

- Основные органы управления мода — ручки громкости (Volume) и обратной связи (Feedback) — ведут себя непредсказуемо: значение скачет при захвате и не соответствует позиции курсора.
- Часть шкалы недостижима, что особенно заметно при регулировке громкости (нельзя выставить средние/высокие значения точным захватом ручки).
- Не покрыто: **F72** документирует только FPS-зависимый `Mathf.Lerp` без `Time.deltaTime`, **F149** — multitouch утечку состояния. Отображение «значение ↔ визуал» нигде не описано.

---

## Сценарий воспроизведения

1. Открыть панель радио, захватить ручку громкости в положении 0% (ручка «вверх»).
2. Не двигая мышь, наблюдать рост значения до ~64% (прыжок на 90°).
3. Установить значение > 90% и попытаться захватить ручку — драг не начинается.

---

## Исправление

Вариант A (минимум): убрать offset из значения — `angle = Mathf.Atan2(dir.x, dir.y) * Mathf.Rad2Deg;` (как в `CursorHandler`).
Вариант B (сохранить offset как «нулевую позицию шкалы»): компенсировать в визуале — `spinnerRect.localRotation = Quaternion.Euler(0, 0, -currentAngle + GetAngleOffset());`.
Оба варианта требуют проверки на живой панели: ручка должна указывать на курсор при драге, захват не должен менять значение.
