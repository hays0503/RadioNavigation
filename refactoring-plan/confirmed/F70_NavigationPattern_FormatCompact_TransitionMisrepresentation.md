# F70: NavigationPattern.FormatCompact() — неверное отображение transition-группы

**Приоритет:** P1 (High)  
**Область:** Logic · NavigationPattern  
**Файл:** `Source/Logic/NavigationPattern.cs:77-107`

---

## Проблема

`FormatCompact()` при `g == pattern.TransitionIndex` (строка 87) выводит всю transition-группу как точки, за которыми следует `" = "`:

```csharp
if (g == pattern.TransitionIndex)
{
    for (int i = 0; i < pattern.ElementsPerGroup; i++)
        sb.Append(".");                              // ← ВСЕГДА точки
    sb.Append(" = ");
    inDashes = true;
}
```

В реальности Consol-сигнал внутри transition-группы содержит смесь точек (до флипа фазы) и тире (после флипа) — примерно половина точек, половина тире. `FormatCompact()` всегда показывает **все точки**, что неверно отражает реальную структуру сигнала.

Кроме того, после `" = "` все последующие группы становятся тире (`inDashes = true`). Если после transition есть ещё группы, они корректно отображаются как тире, но сама transition-группа визуализируется некорректно.

## Пример

Для паттерна с `TransitionIndex=2, ElementsPerGroup=10`:
- Реальность: `.....-----` (5 точек, 5 тире)
- FormatCompact: `..........` (10 точек) — неверно

## Влияние

- Отладочная информация о сигнале не соответствует реальности
- Может ввести в заблуждение при анализе качества приёма
- `FormatCompact()` используется в диагностических целях

## Исправление

Возможные варианты:
1. Учитывать реальный переход внутри группы (сложно, т.к. FormatCompact работает на уровне групп, не элементов)
2. Изменить маркер на `"... = ..."` в середине, а не в начале
3. Документировать, что формат компактный и не претендует на точность

## Риски

- Изменение формата может сломать парсинг логов, если кто-то на них завязан
- Низкий приоритет, т.к. функция диагностическая
