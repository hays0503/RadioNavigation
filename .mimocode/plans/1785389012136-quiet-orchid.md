# План: Создание файлов отдельных проблем аудита (22 issue)

## Конвенция именования
Каждый файл — одна проблема, формат: `PH.PRIORITY_ID_ShortTitle.md`
- PH = фаза приоритета: P0, P1, P2…
- ID = порядковый номер проблемы с предыдущего аудита (C1–C6, M1–M6, MN1–MN9)

---

## Файлы для создания

### P0 — Critical (3 файла)

#### 1. `P0.P7.C1_ThreadSafety_AudioState.md`
- **Проблема:** Состояние гонки между audio-thread и main-thread на `StationState[]` (SonneController.cs, AudioSynthesisEngine.cs, StationState.cs)
- **Severity:** Critical — возможен краш или искажение звука

#### 2. `P0.P7.C5_MHz_BandUnit_Wrong.md`
- **Проблема:** DialConfig.Bands[0] использует `"MHz"` вместо `"kHz"`, диапазон 70–150 (исторически CONSOL VLF = ~30–80 kHz), форматирование выводит `"70.0 MHz"` — ошибка 3 порядка
- **Severity:** Critical — неправильное отображение частоты, вводит пользователя в заблуждение

#### 3. `P0.P7.C4_ReflectionFragility_RadioStoryIntegration.md`
- **Проблема:** Вся интеграция с UBOAT системой событий через runtime reflection (`Type.GetType(...)`), fail-open при крахе, тройное дублирование кода (lines 297-305, 314-321)
- **Severity:** Critical — любой патч game сломает моф без видимых ошибок

---

### P1 — Major (8 файлов)

#### 4. `P1.P7.C2_GodObject_SonneController.md`
- **Проблема:** 508 строк, 7+ ответственностей: аудио-координатор, декодер сигналов, навигационный координатор, диспетчер станций, расчёт курсовых углов, position fixing, Unity жизненный цикл

#### 5. `P1.P7.C3_GodObject_InformationPanelHandler.md`
- **Проблема:** 474 строки, God-class: UI factory, event subscription, display update loop для 4 streams + бизнес-логика (Gaussian decay) внутри MonoBehaviour

#### 6. `P1.P7.C5_DebugLog_AudioPath.md`
- **Проблема:** `Debug.Log()` вызывается из audio callback (`OnAudioFilterRead`) на ~44kHz — может вызвать CPU overhead и фриз игры даже в release build

#### 7. `P1.P7.M4_ImmutableStructs_Mutable.md`
- **Проблема:** Mutable value types (StationState, Measurement, FixResult) без `readonly`, могут привести к багам при копировании по значению

#### 8. `P1.P7.M5_PrefabNames_NotUsed.md`
- **Проблема:** `PrefabNames.cs` константный каталог существует, но только RadioInstaller.c:77 его использует; остальные файлы используют сырые строки `.Find("...")` в 5+ файлах

#### 9. `P1.P7.M2_StaticServiceLocators.md`
- **Проблема:** Static mutable service locator pattern — ToggleHandler.IsRadioOn, RadioHandler.Instance, GroundHandler.groundActive (7 locations), доступ из 8 разных файлов

#### 10. `P1.P7.M6_ComparisonExtensions.md`
- **Проблема:** Extension methods (IsNull(), IsPositive()) вместо нативных C# null-checks и сравнений — код не-idiomatичен для опытных разработчиков C#

#### 11. `P1.P7.M8_O_N_RemoveAt.md`
- **Проблема:** `List.RemoveAt(0)` в SignalRichTextFormatter используется как FIFO — O(n) каждый раз, квадратичный O(n²) на длинных списках; нужно использовать `Queue<SignalEntry>`

---

### P2 — Medium (7 файлов)

#### 12. `P2.P7.M7_MagicNumbers.md`
- **Проблема:** 15+ магических чисел: BfoBase 1000f, cursor offset 90f, spinner range 140f, tick timing 50f — разбросаны по коду без централизованного источник

#### 13. `P2.P7.M1_Monolithic_Main.cs.md`
- **Проблема:** Main.OnLoaded() (97 строк) делает всё: Harmony patches setup, DI-registration-scene listeners, pre-flight checks — три паттерна жизни в одном методе

#### 14. `P2.P7.M3_AudioScheduling_PerFrameInsteadOfPerSample.md`
- **Проблема:** StationScheduler.Tick() в audio callback per-sample @44kHz; state вычисляется тысячи раз между фреймами без необходимости — должен считаться один раз на кадр

#### 15. `P2.P7.M9_ConsolCycleConfig_DeadParameter.md`
- **Проблема:** ConsolCycleConfig.GetForCycleDuration(int) всегда return Cycle120s, игнорирует параметр, misleading API

#### 16. `P2.P7.M4_MissingDeadCode.md`
- **Проблема:** Dead code paths: UpdateStationBeats() never called, GetSignalBuffer() dead overload, Isolated method ImgState(), и т.д. — ~30 строк мёртвого кода в runtime

#### 17. `P2.P7.M10_SpinnerHandler_Lerp_FrameRate.md`
- **Проблема:** SpinnerHandlerBase.OnDrag использует `Mathf.Lerp(..., sensitivity)` без `Time.deltaTime` — скорость плавности зависит от частоты кадров

#### 18. `P2.P7.DeadCode_DebugLogging_BeyondAudio.md`
- **Проблема:** Отладочные `Debug.Log()` вызываются при каждом клике (ZoneHandler:62, GroundHandler:99) и при обновлении сигнала — выделаются в release build

---

### P3 — Minor (8 файлов)

#### 19. `P3.P7.MN1_SpinnerSubclasses_Duplicate.md`
- **Проблема:** VolumeSpinnerHandler и FeedbackSpinnerHandler — полностью одинаковые скелеты с одним параметром DebugTag; нужно объединить в один класс с инжектным тегом

#### 20. `P3.P7.MN4_PlantNullChecks_BeaconData.md`
- **Проблема:** BeaconData имеет null callsigns для german wartime stations (Beauvais, Bayeux...), Plougourvest null frequency — Morse keyer и audio engine не защищены

#### 21. `P3.P7.MN5_LoopFrameRateIndependent.md`
- **Проблема:** InformationPanelHandler.Update() вызывает FindClosestStation для каждого кадра без необходимости; вычисления надо кэшировать/инвокать по событию

#### 22. `P3.P7.C6_NaN_Propagation.md`
- **Проблема:** DialConfig.AngleToFrequency возвращает NaN при валидном band index — две независимые проверки на NaN; если пропустят — artifacts на UI или в bearing calc

## Структура каждого файла (шаблон)

```markdown
# [SHORT TITLE]

## Problem
Конкретные файлы, строки, цитаты кода, объяснение ЗАЧЕМ это проблема.

## Impact
Что произойдёт если оставить без внимания: влияние на юзер-экспириенс или разработчиков — технические подробности.

## Recommended Fix
Шаги реализации с примерами конкретного кода (если применимо), приоритет/зависимость (blocked-by, required-by).

## Verification
Проверка результата fix: unit test names, manual steps, debug assertions, CI gate if any.

## Priority & Dependencies
- blocked-by: N/A or list of blocking refs
```
