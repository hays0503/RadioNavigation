# F200. SonneController.UpdatePosition() — ноль вызывающих: position fix всегда ≈ 0°N 0°E, пеленг-механика мертва

| Поле | Значение |

| **Дата обнаружения** | 2026-08-01 |

---

## Описание

`UpdatePosition(float latitude, float longitude)` определён в `SonneController.cs:307-312`, но **не имеет ни одного вызывающего** во всём репозитории (grep по `*.cs`: только определение и присваивания внутри него). Поля `playerLatitude`/`playerLongitude` (`SonneController.cs:25-26`) навсегда остаются `0.0`:

```csharp
// SonneController.cs:307-312
public void UpdatePosition(float latitude, float longitude)
{
    playerLatitude = latitude;
    playerLongitude = longitude;
    UpdateStationNavigation();
}
```

`UpdateStationNavigation()` (`SonneController.cs:396-441`) вызывается из `Update()` каждые `NavUpdateInterval = 0.2f` (`:329-334`) **безусловно** (без проверки зоны) и вычисляет все пеленги через `CalculateBearing(playerLatitude, playerLongitude, ...)` (`:403-405`) от точки (0,0) — Гвинейский залив. Никакой гармони-патч и ни один компонент не подаёт реальную позицию лодки в мод.

### Каскад последствий

1. **Фикс всегда ≈ 0°N 0°E.** `measurements` наполняется всеми 14 станциями (`:426-433`), `HasEnoughMeasurementsForFix()` (`Count >= 2`) всегда true → `lastFix = PositionFixCalculator.Calculate(measurements)` — пересечение больших кругов, направленных к (0,0), даёт позицию вблизи экватора/нулевого меридиана. `ErrorKm = 0` (см. F16/F168) → `fixText.color = green` (`InformationPanelHandler.cs:385`) — ложный уверенный фикс.
2. **Dot-счёт статичен.** `DotCount`, сектор и сгенерированный Consol-паттерн (`:407-419`) зависят от пеленга от (0,0) и не меняются при движении лодки — основная игровая механика мода (определение пеленга по числу точек) не работает.
3. **UI вводит в заблуждение.** `UpdateFixDisplay()` (`InformationPanelHandler.cs:361-386`) показывает зелёную позицию, которую игрок может принять за реальную.

---

## Влияние

- P0: ядро функциональности мода (позиционирование по Sonne) не функционирует с первого запуска.
- UI демонстрирует ложную уверенную позицию (0°N 0°E, ошибка 0 км) без каких-либо признаков отсутствия данных.
- Не покрыто существующими F-номерами:
  - **F47** — документирует только то, что SAD ссылается на несуществующий класс `PositionTracker` (проблема *документации*, а не рантайма).
  - **F99** — stale fix при `measurements < 2` — другой путь (здесь `measurements` всегда полный).
  - **F131** — станции без частоты в фиксе — ортогонально.

---

## Сценарий воспроизведения

1. Любая игровая сессия, вход в Sonne-зону (зона 1).
2. Инфо-панель показывает «Fix: 0.0000° N 0.0000° E» зелёным, `Beacons: 14`, `Error: 0.0 km`.
3. Движение подлодки на любое расстояние не меняет ни фикс, ни число точек.

---

## Исправление

1. Подключить реальный источник позиции: патч на игровое API позиции лодки (аналогично патчам `RadioStory` в `Main.cs`) и вызывать `UpdatePosition()` из него; либо добавить интерфейс `IPositionProvider`, инжектируемый в `SonneController`.
2. Пока фид отсутствует — не показывать фикс: скрыть `UpdateFixDisplay()` при неинициализированной позиции (например, флаг `positionAvailable`) и выводить «Position: NO DATA» вместо зелёного ложного фикса.

## Зависимости

- **F204** — антимеридиан-агрегирование в `PositionFixCalculator` станет воспроизводимым только после подключения позиции.
- **F16/F168** — `ErrorKm = 0` маскирует погрешность; без реальной позиции фикс всегда выглядит «идеальным».
- **F99** — stale fix: после фикса F200 нужно пересмотреть валидность по времени измерения.
- **F128/F137/F190/F191** — численные дефекты `FindIntersection` проявятся при реальных данных.
