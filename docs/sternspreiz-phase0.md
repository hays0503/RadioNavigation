# Sternspreizglas — Phase 0 runtime gate

## Назначение и ограничения

Этот документ ведёт только runtime-эксперимент feasibility для эффекта
Sternspreizglas секстанта. **Он не выбирает production-архитектуру и не
авторизует реализацию PSF или celestial-рендерера.** `IOpaqueImageEffect`
с шейдерным PSF (G+E) остаётся непроверенным кандидатом.

Phase 0 добавляет opt-in `SternspreizPipProbeEffect` на обе PIP-камеры
секстанта. Фикстура использует встроенный слой Unity `Default` после проверки,
что бит присутствует в масках Main/PIP-камер и в масках SRP-проходов обоих
PIP. Нативный source-сентинел подавляется только вокруг вызова
`DeepPipeline.RenderDeferredCamera`/`RenderForwardCamera` зарегистрированной
PIP-камеры; финализатор Harmony восстанавливает его renderer при нормальном
или исключительном выходе. Маски и проходы Main Camera никогда не пишутся.
Фикстура использует один общий disposable sentinel-меш. Она читает живую
ссылку на меш `StarSkyRoot` для телеметрии, но никогда не меняет и не рисует
этот меш. Звёзды, планеты, Луна и Sun не модифицируются. Preference по
умолчанию OFF:

```text
RadioNav.SternspreizProbe = 0  OFF (default)
RadioNav.SternspreizProbe = 1  callback/source-destination pass-through test
RadioNav.SternspreizProbe = 2  PIP-local source suppression + sentinel DrawMesh/depth test
RadioNav.SternspreizProbe = 3  PIP-local StarSkyRoot suppression, pass-through only
```

Mode 3 добавлен после живой приёмки Phase 0 на 15 проверок. Это отдельный
feasibility-диагностический режим; живая приёмка супрессии задокументирована в
[`sternspreiz-phase1a-source-suppression.md`](sternspreiz-phase1a-source-suppression.md)
(телеметрия PASS по каждому PIP, Main цел; визуальное отсутствие звёзд —
PARTIAL). В отличие от mode 2, он отключает актуальный renderer `StarSkyRoot`
только вокруг рендера левого/правого PIP и не выдаёт `DrawMesh`. TOD Sun не
обрабатывается.

`DrawMesh` режима mode 2 — аддитивный диагностический оверлей поверх
disposable тестовой фикстуры; это **не** предназначенная production-замена
изображения. Production должен заменять PIP source image без изменения Main
Camera и не оставляя необработанное celestial-изображение под штрихом.

Нативное TOD Sun не затрагивается Phase 0. Любая будущая обработка Sun —
отдельный интеграционный блокер, пока живой тест не докажет, что нативное TOD
Sun можно исключить из обеих PIP-камер до обработки изображения мода.

Устанавливайте preference операцией UBOAT MCP `prefs_set` (тип `int`) или
оставьте `0`. Существующий снапшот `sextant` включает `sternspreizPhase0`.
Маски SRP-проходов читайте через
`reflect_call(type="UBOAT.Mods.RadioNavigation.SextantProbe", method="PassDump")`,
сырой вид захватывайте через `screenshot_frame`; используйте оба как
доказательства визуала/состояния проходов. После эксперимента верните
preference в `0` и закройте секстант.

## Инструментальные доказательства

Снапшот секстанта сообщает, на глаз:

- `callbackCount`, `lastFrame`, `enabled`, `mode`;
- `sourceValid`, `destinationValid`, `depthHandleValid`, `targetsAlias`, размер цели;
- `drawIssued`, `depthDrawIssued`, ID/число вершин sentinel-меша;
- наблюдаемые ID/число вершин `StarsMesh.sharedMesh` и `starsMeshStable`;
- ошибку setup/execute, плюс счётчики компонентов обоих PIP и culling-маски камер.

Это диагностические наблюдения, а не доказательство визуальной маршрутизации или глубины. Каждый снапшот `sourceScopeLeft/Right` дополнительно сообщает, установлен ли хук рендера этого PIP, счётчики вызовов по путям, счётчики супрессии/восстановления и включён ли renderer между рендерами. Для видимости сентинелов используйте скриншоты, для масок по проходам — SRP pass dump.
Видимая тестовая отрисовка переиспользует world-трансформ source-фикстуры. Depth-отрисовка проецирует актуальный окклюдер в каждый PIP, затем кладёт общий меш дальше на том же луче камеры; это исключает трактовку пространственно несвязанных передних/задних квадов как depth-тест. Переключается только source-`Renderer`, и только пока зарегистрированный PIP входит в игровой render-метод; восстанавливается в финализаторе. Окклюдер остаётся включённым, чтобы валидировать глубину.

### Догоняющая реализация — PIP-local супрессия

- Недоступный аллокатор кастомных слоёв заменён встроенным битом `Default`,
  явно проверенным по живым маскам камер/проходов. Этот слой уже общий для
  Main и обоих PIP; подавляется только disposable source-renderer на рендер PIP.
- Добавлен `SternspreizPipRenderScopePatch`, оборачивающий оба
  `DeepPipeline.RenderDeferredCamera` и `RenderForwardCamera` по точной
  сигнатуре. Per-PIP source renderer отключается в префиксе и
  восстанавливается финализатором Harmony; счётчики снапшота показывают вызовы,
  супрессию, восстановление и состояние renderer. Колбэк Mode 2 закрывается с
  ошибкой, если супрессия не активна для того же PIP и кадра.
- Декомпилировали установленный `com.dws.pipeline.Runtime.dll` для проверки
  порядка: `RenderDeferredCamera` выполняет сборку/рендеринг камеры и вызывает
  `IOpaqueImageEffect.RenderImageOpaque` до возврата, поэтому колбэк наблюдает
  активный suppression scope. Финальная живая верификация записана ниже.
- Живой тест закрытия mode-2 выявил, что фикстура на Default-слое осталась
  видимой в Main после отключения PIP-камер. `Close()` теперь suspend-ит оба
  renderer фикстуры и оба компонента колбэков, сохраняя ровно один
  сконфигурированный компонент на глаз для переоткрытия.
- Ранняя ошибка аллокатора 2026-09-27 остаётся историческим доказательством
  заменённого дизайна на двух кастомных слоях; её BLOCKED-статус заменён
  финальной runtime-приёмкой ниже.
- Первая живая попытка с пересмотренной layer/scope-маршрутизацией дошла до
  настройки фикстуры, но сообщила `Unlit/Color shader unavailable`; живой
  `Shader.Find` подтвердил, что `Hidden/Internal-Colored` и `Sprites/Default`
  присутствуют, а `Unlit/Color` вырезан. Фикстура теперь резолвит доступный
  встроенный шейдер и имеет fallback. Фикстура в той попытке не создалась,
  поэтому source-suppression хуки простаивали и ни один runtime-критерий кроме
  OFF не оценивался; fallback шейдера добавлен до принятого прогона.
