## Симптом и контекст

Наша небесная геометрия (звёзды, линии созвездий, планеты, диск Луны, диск Солнца) — это
**реальная геометрия** на оболочке ~3700 м, материалы `Queue=Transparent` (3000), `ZWrite Off`,
`ZTest LEqual`. Облака UniStorm при качестве выше «Simple» — **ray-marched** внутри дому-меша
`UniStorm Volumetric Clouds` (~5.5 км) плюс частицы. Наблюдаемый дефект: звёзды рисуются
**поверх** облаков.

## Расстояния (живые замеры 2026-09-29, из запущенной игры через мост)

| Слой | Объект / материал | Дистанция |
|---|---|---|
| Наша небесная геометрия | звёзды, линии созвездий, планеты, Луна, Солнце | ~3700 м (`CameraResolver.SafeRadius` = `min(3900, farClip*0.85)`) |
| Облака UniStorm (ray-march) | `UniStorm Volumetric Clouds` (2 инстанса, активен один), материал `UniStorm Cloud Layer` | ~5.5 км |
| Частицы облаков | `Cloud Emitter` / `Clouds Layer`, материал `Clouds Material` | 3900 м (высота) |
| Тени облаков | `Clouds Shadows` (`CloudShadows`) | сейчас невидимы |
| Небо игры: Луна | `Moon` | ~6.2M м |
| Небо игры: Солнце | `Sun` | ~2.1M м |
| Небо игры: звёздный купол | `Stars` | ~2–7M м |

Отдельный облачный меш существует только на «Simple»; выше него облака живут в дому и частицах.

## Гипотеза механизма

Unity сортирует прозрачные рендереры **back-to-front** (дальние — раньше). Наш слой (3.7 км)
**ближе** облачного дому (5.5 км), поэтому облака рисуются раньше нас, а наши квады — поверх
них; глубина у облаков не пишется, отсечь нас нечем. Небо игры лежит на 2–6M м, **дальше**
облаков, поэтому оно рисуется первым и облака корректно перекрывают его.

Лечение, которое проверяет инструмент: **опустить очередь нашего материала ниже облачной** —
тогда облачный проход смешивается ПОВЕРХ неба.

## Инструмент (инертен по умолчанию)

- `Source/Logic/SkyRenderQueuePolicy.cs` — чистая политика: `Off = 0`, `MinQueue = 1000`,
  `MaxQueue = 3500`, `Clamp(int)`, `TryApply(Material, int)` (no-op на null/`<= Off`,
  кламп, пишет `renderQueue` только при отличии).
- `Source/Logic/SkyRenderQueueSwitch.cs` — `internal static int QueueOverride` + `Set/Reset`;
  драйвится живьём из MCP-моста через reflect.
- Вызовы (покадрово, рядом с существующими обновлениями материала): `StarsMesh.cs`,
  `ConstellationMesh.cs`, `PlanetRenderer.cs`, `MoonDiscRenderer.cs`, `SunDiscRenderer.cs`.
- Тесты: `Tests/SkyRenderQueuePolicyTests.cs` (7 фактов) + заглушка
  `Tests/Stubs/UnityEngineMaterial.cs`.
- Гейт SourceCheck: `SkyRenderers_RouteThroughQueueOverride` (мутационно проверен: убрать
  вызов из `PlanetRenderer` → FAIL с «…its sky content would paint over the clouds»;
  вернуть → PASS).

### Как крутить живьём

```text
reflect_set UBOAT.Mods.RadioNavigation.SkyRenderQueueSwitch.QueueOverride 2900
reflect_set UBOAT.Mods.RadioNavigation.SkyRenderQueueSwitch.QueueOverride 3000
```

**Семантика `QueueOverride`:** `0` означает «ничего не писать». Это **НЕ** откат материала,
который уже был изменён прежним оверрайдом, — материал остаётся на последнем записанном
значении. Чтобы вернуть небо к собственному поведению шейдера, ставьте **3000** (собственная
очередь шейдера), а не `0`.

## Ограничение моста: материал по имени не читается

`McpReflect.FindInstance` (`Mods/McpBridge/Source/Logic/McpReflect.cs:481-499`) применяет фильтр
по имени только когда тип — `Component`; **Material** им не является, поэтому
`material.renderQueue` живьём **прочитать нельзя** — очередь закреплена только исходником и
гейтом. Чтения вида `renderQueue=2000` с `warning:fallback-used` относятся к **чужому**
материалу (`MbOutlines/Outline A`) и использовать их нельзя.
