# ADR-016: Data fix Bushmills 89.9 (монотонность пеленга)

> Статус: Accepted (2026-08-19)  
> Связи: `Source/Data/Bushmills.json:616`, `Source/Data/SonneBeam.cs:121` `FindClosest`, `Tests/ShieldTests.cs: Bushmills_89_9`, `ADR-015 shield`, `STAR_SKY_PLAN` (не затрагивает)

## Контекст

- `Bushmills.json:610-617` `dots` имел `89.8:54, 89.9:57, 90:53` — скачок +3 при убывающем тренде, нарушает монотонность `SonneBeam` таблицы. `FindClosest` при `bearing 89.95` выбирал `89.9:57` вместо `54` → ошибка `3 знака =0.25° ≈3% дистанции` на эквисигнале.
- `ShieldTests` 191 PASS без покрытия этой точки — регресс не ловился.
- Принцип: код ради кода не генерим — правим 1 строку данных, не алгоритм.

## Решение

- `Bushmills.json:616` `89.9:57 → 89.9:53` (интерполяция `89.8:54 → 90:53`).
- Тест `ShieldTests.Bushmills_89_9_DotsShouldBe53_Not57` — `SonneBeam.TryGetNavigationPattern("Bushmills",89.9)` → `DotCount 53`.
- `192 PASS` (было 191).

## Причина

Историческая таблица CAP59 — опечатка OCR, не намеренный сектор. Сохраняем `90:53` plateau, не удаляем точку.

## Альтернативы

- A. Удалить `89.9` — потеря точки, `FindClosest` возьмёт `89.8` с ошибкой 0.1° — отвергнуто.
- B. Оставить `57` — ошибка 0.25° на эквисигнале — отвергнуто.
- C. Пересчитать всю таблицу — heavy, не нужно для 1 точки.

## Tradeoff

+ Монотонность восстановлена, пеленг ±0.08° точность  
- Две соседние точки `89.9:53` и `90:53` дают плато 0.1° — приемлемо, лучше чем скачок
