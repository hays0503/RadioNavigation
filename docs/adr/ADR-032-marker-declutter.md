# ADR-032: Screen-space деклаттер карт-маркеров (greedy min-gap)

> Статус: Accepted (2026-09-09)  
> Связи: `Source/Logic/MarkerDeclutter.cs`, `Source/UI/NavMapMarkerBase.cs`, `Source/UI/LighthouseMapMarker.cs`, `Source/Logic/LighthouseMarkerSizing.cs`, `Source/Logic/RadioNavDiagnostics.cs`, `Tests/MarkerDeclutterTests.cs`, ADR-027, ADR-031

## Контекст

- `NavMapMarkerBase` рисовал **все** маркеры флота каждый кадр на любом зуме: 555 иконок = каша на стратегическом зуме (27 скриншотов пользователя). Фон 80×80 с альфой 0.9 проектировался под 5 станционных маркеров — на сотнях иконок превращался в кремовый суп.
- Хитбокс 96 px (1.5× иконки) при плотной застройке ловил курсором не тот маяк.
- Подавление SetActive(false) при наведении вешает тултип: деактивированный корень не получает PointerExit, события наведения ломаются.

## Решение

- `MarkerDeclutter.Select(items, gap, shownByViewIndex)` — чистый C# (только System, как `LighthouseMarkerSizing`, тестируется офлайн). Жадный отбор: сортировка Forced → Priority desc → ViewIndex asc (детерминизм независимо от порядка входа), элемент подавляется при наличии принятого ближе gap; O(n²) по принятому множеству (n = сотни, дёшево).
- **Gap = 1.3 × iconPx в мировых единицах** (× `UnitsPerPixel`) — самоадаптация к зуму без WorldToScreenPoint: дальний зум прячет плотную массу, ближний показывает всё, что влезает. 1.3 удерживает фоны 80-юнитов (1.25× иконки) соседей от касания. Gap ≤ 0 → показать всё; NaN-координаты показываются, но не занимают места.
- **Forced (пин/ховер) никогда не подавляется** и занимает место первым — тултип не может остаться на скрытом корне.
- Хуки в `NavMapMarkerBase`: virtual `DeclutterEnabled` (**default false** — 5 станционных маркеров не тронуты) и virtual `Priority(index)`; `LighthouseMapMarker` включается с `Priority => FireHeightM`. Ховер-трекинг `hoveredIndex` в базе. `Suppressed`-флаг в MarkerView гасит лишние SetActive; аллокаций нет (скретч-буферы, кэшированный `Comparison`).
- Хитбокс 96 → **76 px** (96/64 = 1.5× иконки перекрывался бы внутри gap 1.3); фон **alpha 0.9 → 0.5**.
- Диагностика: ключ `RadioNav.LighthouseDeclutterStats` (PlayerPrefs, default false, троттл 2 с): `declutter: shown=N/total iconPx=X`.
- Zoom-LOD полосу пользователь отверг (ADR-031): одинаковые правила, зум-адаптацию даёт сам gap.

## Причина

Деклаттер — единственный механизм, который решает читаемость при любом зуме без изменения данных и правил: физический смысл (иконки не должны накладываться) один на стратегическом и ближнем зуме. Приоритет fireHeight выводит навигационно значимые маяки наверх.

## Альтернативы

- A. Прятать по дистанции камеры (LOD-полоса) — отвергнуто пользователем: разные правила на разных зумах.
- B. Кластеризация с агрегат-иконкой («+12») — отвергнуто: усложняет UI, теряются пины навигационных огней.
- C. Прятать всегда кроме крупнейших — отвергнуто: на ближнем зуме все огни навигационно полезны, деклаттер и так показывает всё, что влезает.

## Tradeoff

+ Стратегический зум: 32/555 показано (94% подавлено), карта чистая; ближний: 124/555 — адаптивно. После ADR-031: 29/210.
− Жадный min-gap не оптимален глобально (не максимальное независимое множество) — для маркеров неважно, детерминизм важнее.
− Ховер/пин по-прежнему не автоматизируется MCP (нет мыши) — логика пина покрыта юнит-тестом `Select_ForcedItem_ClaimsSpaceDespiteLowestPriority`.
