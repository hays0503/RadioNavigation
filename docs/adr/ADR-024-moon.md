# ADR-024: Луна в STAR_SKY

> Статус: Accepted (2026-08-19)  
> Связи: `STAR_SKY_PLAN.md`, `CELESTIAL_REALISM_PLAN.md`, `Source/Logic/AstroMath.cs`, `Source/Logic/CelestialEphemeris.cs`, `Source/Logic/MoonDiscRenderer.cs`

## Дополнение: действующая реализация (2026-10-04)

Луна реализована; **low-precision элементы, пятый planet-quad и системное время
ниже — исходная версия 2026-08-19, не текущая архитектура**. Подход заменён P2
в `CELESTIAL_REALISM_PLAN.md`, дата исходного Accepted сохранена.

- `AstroMath.MoonRaDec` — усечённый ряд Meeus гл.47 (долгота, широта, нутация),
  а не прежняя кеплерова база и не полный ELP2000. Оценка порядка 0.05° в коде
  не даёт гарантии 10″ для всех дат кампании.
- `MoonDistanceKm` использует **косинусный** ряд расстояния; `MoonParallaxDeg`
  и `MoonTopocentricRaDec` учитывают положение наблюдателя. Renderer,
  идентификация, forecast и reduction используют топоцентрическую Луну,
  иначе картинка и Hc расходятся до ≈57′ у горизонта.
- `PlanetRenderer` содержит четыре планеты. Луна — отдельный `MoonDiscRenderer`
  с `MoonPhaseDisc`: терминатор и направление освещённого края вычисляются по
  направлениям Солнца/Луны, а не одному синодическому таймеру. Видимый диаметр
  1.04° — художественное ×2, не заявленный физический диаметр.
- Время берётся через `GameTimeResolver` из `GameTime.GmtDateTime`;
  `CelestialEphemeris.JdFor(Moon, utc)` применяет калибровку Δt. Лунная ветка
  использует UT, солнечная — отдельный TT; LST/GHA нельзя подменять солнечным TT.
- `MoonIllumination` получает долю из геоцентрической элонгации Солнце–Луна.
  Фазовый renderer использует отдельную текстуру, а не затухание целого quad.
  Полные члены, либрация и внешняя визуальная точность не объявлены проверенными
  только на основании тестов конечности или исторических 208 PASS.

Это обновление документации не проводило новых лунных замеров в игре.
Текущая тестовая база — `DOCS.md`; исходный Phase 0 протокол остаётся в ADR-020.

## Исходная запись решения (2026-08-19)

## Решение

- Добавить `MoonRaDec` на основе упрощённых орбитальных элементов Meeus/low-precision.
- Переводить лунные эклиптические координаты в экваториальные через наклонение эклиптики.
- Рендерить Луну в том же mesh, что и планеты, отдельным пятым camera-facing quad.
- Использовать синодический период для освещённости: `0.5 * (1 - cos(phase))`.
- При нулевой освещённости alpha quad становится нулевой.

## Ограничения

- Это не усечённый ELP2000 и не подтверждает требование точности около 10″.
- Не учитываются полные лунные члены, оптическая либрация, аберрация и световое время.
- Перед заменой игровой Луны нужна Phase 0 проверка на датах 1942-06-15 и 1943-01-10 в 00:00/06:00 UT.
- Текущее время берётся из `DateTime.UtcNow`; подключение `GameTime.GmtDateTime` остаётся отдельным этапом.

## Проверка

- 208 тестов проходят.
- Проверены конечность RA/Dec и противоположные значения освещённости новолуния/полнолуния.
