# ADR-033: Ручное счисление по Солнцу, Луне и звёздам

> Статус: Accepted (2026-09-16)
> Связи: `Source/Logic/CelestialBody.cs`, `Source/Logic/CelestialEphemeris.cs`, `Source/Logic/BodyRecommendation.cs`, `Source/Logic/SextantRunningFix.cs`, `Source/UI/SextantStarId.cs`, `Source/UI/SextantWorksheet.cs`, `Source/UI/FixCardComposer.cs`, `Source/UI/SextantBodiesReadout.cs`, `Source/UI/SextantHelpPanel.cs`, ADR-024, ADR-025, SEXTANT_PLAN

## Контекст

- Секстант (SEXTANT_PLAN v1.9–v1.13) умел только **running fix по Солнцу**: `SextantWorksheet.CaptureObservation` жёстко отклонял любое тело, кроме «Солнце», а `RunningFixCalculator.BuildObservation` был прибит к `AstroMath.SunRaDec` и калибровке SUNDRIFT.
- Звёзды идентифицировались (57 навигационных + каталог), Луна рисовалась модом и попадала в справочник, но **записать их замер было нельзя**, а Луна даже не входила в конус идентификации.
- Математика фикса (`BuildLop`/`IntersectLops`/`CalculateFix`) уже была телос-агностична — не хватало только идентичности тела в наблюдении.
- Эфемериды разные по источнику: Солнце рисует игра (нужна калибровка Δt), Луну и звёзды рисует мод (чистый UTC). Смешивать их в одной серии надо корректно.
- Игра **не моделирует** рефракцию, параллакс Луны и наклон горизонта (dip); эфемерида Луны низкоточная (ADR-024, ±0.3°). Пользователя надо об этом предупредить, а не молча выдавать «точный» фикс.

## Решение

- **`CelestialBody`** — чистая модель тела: `Kind {None,Sun,Moon,Star}`, `Name`, `Hip`; фабрики `Sun()/Moon()/Star(hip,name)`; `AsciiName` для карт-тултипа (TMP без кириллицы).
- **`CelestialEphemeris`** — единственная точка маршрутизации эфемериды: `Compute(body, utc)` → `SunRaDec` / `MoonRaDec` / `StarCatalog` по HIP; `JdForKind` → `CalibratedJd` **только для Солнца**, иначе `ToJulianDay`. Ре-инлайн Meeus в контроллер запрещён SourceCheck-гейтом `CelestialEphemeris_RoutesBodies`.
- **`SextantObservation`** хранит `BodyKind/BodyName/BodyHip/BodyRaDeg/BodyDecDeg`; `BuildObservation(..., CelestialBody)` — тело-осознанный, старый 4-арг делегирует на `Sun()`; `RecomputeHcAz` использует замороженные RA/Dec (телос-агностичен).
- **`SextantStarId`** возвращает `IdentifiedBody`: конус Sun→Moon→звезда, ближайшее побеждает; Луна — при `alt>0` и `MoonIllumination ≥ 0.05`.
- **Понятность (полный пакет):**
  - правая колонка: азимуты к высотам, статус Луны («под горизонтом» / «новая»), строка «→ Второе светило: … (ΔAz …)» через `BodyRecommendation` (кандидат ближе к 90° от азимута №1, alt ≥ 10°);
  - карточка: имя тела в блоке «НАБЛЮДЕНИЕ №n», флаг «Луна ±0.3°», «низко — грубо» при Ho < 10°, порог «a > 30 NM — проверьте наведение», «Линии совпадают — разнесите светила по азимуту» при пересечении < 3°;
  - «Ошибка от счисления» → **«Δ от места игры (проверка)»** (эталон — истинная позиция игры, а не счисление; это самопроверка замеров);
  - футер карточки и экранная справка по клавише **P** (`SextantHelpPanel`) с расшифровкой γ/SHA/GHA/λg/LHA/δ/hb/h1/Az/a, порядком действий и блоком допущений.
- **Допущения раскрываются, а не считаются:** рефракция, параллакс Луны, dip не вносятся в математику (замер согласован с тем, что рисует игра), но перечислены в карточке, справке и README.

## Причина

Секстант — инструмент измерения высоты светила; ограничение «только Солнце» было искусственным гейтом, а не физикой. Одно тело-осознанное наблюдение + маршрутизация эфемериды даёт классический фикс по двум звёздам (Δt≈0) и running fix «Солнце→звезда»/«звезда→Луна» без новой математики. Явное раскрытие игровых допущений честнее, чем попытка компенсировать то, что игра не моделирует (компенсация внесла бы расхождение с видимым небом).

## Альтернативы

- A. Оставить только Солнце — отвергнуто: запрос автора, звёзды/Луна уже на небе и в UI.
- B. N тел + МНК — отложено: текущая модель ровно 2 наблюдения; МНК требует переработки UI (список наблюдений). Не отвергнуто навсегда, вынесено за объём.
- C. Планеты (Венера/Юпитер/Сатурн/Марс) — отложено: рендерятся `PlanetRenderer`, но вне текущего запроса.
- D. Считать поправки (dip/рефракцию/параллакс) — отвергнуто: игра их не моделирует, поправка рассинхронизировала бы замер с видимым диском; вместо этого — явное предупреждение.

## Tradeoff

+ Один фикс-калькулятор на все светила; Луна и звёзды стали полноценными целями; игрок видит, чем мерил, чем мерить вторым и чего ждать от модели.
− Фикс по Луне грубее (low-precision ±0.3° ≈ 18 NM) — раскрыто в UI, не спрятано.
− Смешанная серия «Солнце + звезда» использует разные эфемеридные часы (Δt vs UTC) — корректно относительно отрисованного неба, но не «единый альманах»; задокументировано.
− Серия не переживает save/load (решение автора) — только док.

## Регрессионные фиксы (v2.3, 2026-09-16)

Глубокий аудит выявил и закрыл:
- **F1 (High): Hip=0 sentinel.** `SextantStarId.TryFindStar` не фильтровал `Hip=0` (17 строк каталога с разными координатами); `TryGetStarRaDec(0)` возвращал первую строку (133.534/48.332) для любой из них → тихо неверный фикс. Фикс: `CelestialEphemeris.IsSightableStar(hip) => hip > 0` + guard в `TryGetStarRaDec` + пропуск в `TryFindStar`.
- **N1: латентный fallback.** `BuildObservation` при `Compute==false` подменял эфемериду Солнцем. Фикс: `SextantWorksheet.CaptureObservation` отклоняет тело без эфемериды (`WarnOnce` + лог). SourceCheck-гейт `SextantStarId_SkipsNoHipSentinel`.
- **N2: порог «линии совпадают».** Снижен 3° → **1°** (`RunningFixCalculator.MinUsableCrossingAngleDeg`, `IsCrossingUsable`) — меньше риск заблокировать пригодный фикс.
- **N3/N4: контекстный совет.** `FixCardComposer.GeometryAdvice(crossDeg, sameBody)` / `CoincidentMessage(sameBody)`: одно тело → «разнесите замеры по времени», разные → «разнесите светила по азимуту».
- **F3: рекомендация ≠ тело №1.** `BodyRecommendation.Recommend(..., excludeName)` + `SextantWorksheet.Observation1Name`.
- **V1: диагностика Лун.** `SextantGameSun.TryGetMoon`/`LogMoonParity` (PlayerPrefs `RadioNav.MoonDiag`, throttle 10 с, cached reflection): сравнение игровой TOD_Sky Луны с мод-Луной. `sep < 0.3°` → совпадают; `sep > 0.5°` → две Луны.
- **Планеты** (Венера/Юпитер/Сатурн/Марс) видны, но не счисляются — отмечено в справке и README.

Гейты после фиксов: `tests.ps1` 812, `SourceCheck` 53, PVS clean, complexity ≤15, RN без новых.

## Лунная калибровка (v2.4, 2026-09-16)

In-game MOONDIAG (`RadioNav.MoonDiag=1`) показал, что мод-Луна и игровая Луна
расходятся на **≈1.6°** (`sep=1.60–1.62`, `dalt≈-0.75`, `daz≈1.49`). Это
количественно объясняется тем же временным сдвигом игрового неба, что и
SUNDRIFT: 6.6 мин × 15.04°/ч (суточное движение) ≈ 1.65°.

Решение (вариант A, без reflection в третью сторону): **распространить Δt на
Луну** согласованно во всех точках:
- `CelestialEphemeris.KindUsesCalibration` — Sun **и Moon**; `JdForKind` для
  Луны → `CalibratedJd`. Звёзды остаются plain UTC.
- `PlanetRenderer.RebuildMesh` — Луна рисуется по `moonJd`/`moonLst`
  (калиброванные), планеты — по plain.
- `SextantBodiesReadout.AppendMoon`, `SextantStarId.TryFindMoonCos`,
  `SextantController.TryGetOwnMoon` — калиброванный jd.
- Δt=0 → поведение идентично прежнему.

Проверка: MOONDIAG `sep` должен упасть с ~1.6° до ≲0.3°. Если остаток
велик — у игры другая лунная модель, и вариант A не сработал (тогда B/принять).
