# ADR-031: Fire-height curation — малые огни (<15 м) в LeuchtfeuerMinor.json

> Статус: Accepted (2026-09-09)  
> Связи: `Source/Data/Leuchtfeuer.json`, `Source/Data/LeuchtfeuerMinor.json`, `Tools/Exclude-MinorLights.ps1`, `Source/Data/LeuchtfeuerRegistry.cs`, `Source/Logic/LighthousePlacer.cs`, ADR-030, ADR-032

## Контекст

- После ADR-030 флот = 555 (554 театральных registry + Wangerooge). Пользователь прислал 27 скриншотов: карта выглядит как «мусор» — сотни мелких моловых/пирсовых огней рисуют кашу и на карте, и в 3D.
- Типология DB не помогает: поля `type` нет «Lighthouse» (370 Breakwater light, 51 Warning light, …) — единственный критерий размера огня = `fireHeight`.
- Распределение по театру (554): <10 м — 209; 10–<15 — 136; 15–<20 — 133; 20–<30 — 32; ≥30 — 44; битых/неизвестных — 0.
- Решение пользователя (2026-09-09): порог **≥15 м по fireHeight** → остаётся 210 (209 registry + Wangerooge); малые — в архивный файл, «возможно потом удалим». Zoom-LOD-полосу отверг («Нет, одинаковые правила» — читаемость дальнего зума обеспечивает деклаттер, ADR-032).

## Решение

- `Tools/Exclude-MinorLights.ps1` переносит театральные записи с fireHeight < 15 м из `Leuchtfeuer.json` в `LeuchtfeuerMinor.json` (обёртка `{count, reason, entries}`; рантайм файл не читает). Скопирован по образцу `Exclude-WaterBeacons.ps1` (ADR-030): `-DryRun`, UTF-8 no BOM, `\uXXXX`-декод после `ConvertTo-Json` (MiniJson не понимает `\u`).
- **Двунаправленная идемпотентность**: повышение `-MinHeight` уводит больше записей в архив, понижение возвращает их в реестр (классификация — чистая функция записи). Итог — без потерь (lossless) репартиция: каждая запись попадает в файл, который выбрал её предикат.
- **Без дедупликации**: составной ключ `code|lat3|lon3` коллизирует у разных огней — реальный случай `E1197.x` Outer/Inner Mole Head (Челле-Лигуре, Италия) делит код и округлённые координаты. Первая версия с дедупом уронила консервацию (551+345 ≠ 897) и была исправлена до записи файлов; дубликаты — только `Write-Warning`.
- Консервация: 897 = 552 (реестр) + 345 (архив); театр в реестре = **209**; флот = **210**.
- Рантайм: `LeuchtfeuerRegistry` читает только `Leuchtfeuer.json` — фильтр сработал автоматически; комментарии-счётчики (реестр, маркер) и тест-пин `Profiles.Count` 540..570 → 200..220 обновлены.
- Stale-cleanup (ADR-030 механизм) на старом сейве удалил только **3** группы (B1096 ×2, B1108 — соседи игрока, остатки водной эпохи): 3D-группы материализуются только возле игрока, массового разрушения 345 групп нет, капа не требует.

## Причина

Данные чистятся один раз, как в ADR-030; рантайм-гейт по высоте добавил бы проверку в `EnabledFleet()` на каждый старт без выигрыша. Архивный файл сохраняет данные для будущего пересмотра порога.

## Альтернативы

- A. Рантайм-гейт по fireHeight — отвергнуто: та же логика, но проверка на каждый старт и грязный флот.
- B. Порог 10 м (осталось бы 345) — отвергнуто: пользователь выбрал 15 м по скриншотам.
- C. Zoom-LOD (прятать малые только издалека) — отвергнуто пользователем: одинаковые правила на всех зумах.
- D. Дедуп по составному ключу при переносе — отвергнут после находки E1197.x: потеря легитимного огня.

## Tradeoff

+ Флот 210 (был 555): карта и 3D чистые, маркеров -62%, деклаттеру хватает (29/210 на стратегическом зуме).
− 136 огней 10–15 м тоже ушли (формально «средние») — зафиксированы в архиве, порог возвращается понижением `-MinHeight`.
− `countries` в реестре не пересчитывается (как в ADR-030) — информационное поле.
− Сообщение stale-cleanup было «land curation» → заменено на нейтральное «data curation».
