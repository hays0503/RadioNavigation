# Живая диагностика: что именно доказано

Актуально **2026-10-04**. Используется McpBridge / `uboat-mcp` **0.10.0**,
HTTP `http://127.0.0.1:28777`. Полные маршруты и результаты инструментальной
приёмки находятся в соседнем проекте:
[ROUTES.md](../../McpBridge/ROUTES.md),
[INSTRUMENTS_ACCEPTANCE.md](../../McpBridge/INSTRUMENTS_ACCEPTANCE.md).
Это внешние ссылки рабочей установки, не файлы поставки RadioNavigation.

## 1. Доказательства разного уровня

| Наблюдение | Что подтверждает | Чего не подтверждает |
|---|---|---|
| build / SourceCheck / pure-тесты | компиляцию, API-контракты, проверенную математику и структуру вызовов | загрузку модифицированного Source игрой, GPU submission, внешний вид |
| `render_snapshot` / `/render/snapshot` | текущие camera/RT identity, pose, FOV, culling rect, attachments, GPU/API/process | что меш отправлен GPU или последний кадр уже presented |
| RenderDoc draw / pixel history | submission и вклад в конкретный захваченный проход/пиксель | широкий набор переходов и качество всех последующих кадров |
| `screenshot_frame` / `/screenshot?mode=frame` | полный UI-композит наблюдаемого backbuffer | доказанную свежесть presented-frame: `fresh` и `presentedFrame` могут быть `null` |
| `accepted=true, verified=false` от ввода | принятие/доставку команды выбранным способом | успешное игровое действие; нужно прочитать постусловие |
| успешный rollback / пустой settings diff | восстановление проверенных preimage-настроек | сохранность неохваченных ключей, сейвов и состояния сцены |

`ok:false` — ошибка, даже при HTTP 200. Адаптер возвращает MCP `isError` и
структурированный результат; batch по умолчанию останавливается при ошибке.
Недоступный лог не доказывает отсутствие ошибки.

## 2. Безопасный порядок проверки

1. Снять baseline: PID + creation time игры, camera/player/transition,
   pause/time scale, разрешение, явный список prefs с типами и значениями.
   Сохранить хеши защищённых файлов. Не переписывать acceptance-сейвы:
   `OpenCode_LampPIP_Acceptance.save`, `OpenCode_PIP_Frame_Acceptance.save`.
2. Убедиться, что `/state` сообщает готовность загрузки, а свежий лог —
   реальную инициализацию `[RadioNav]` и отсутствие `error CS`. `modLoaded`
   один не доказывает инициализацию сборки.
3. До записей перечислить объекты (`reflect_instances`, `scene_query`) и
   выбрать однозначную identity. Reflection/components/input — строгие
   селекторы по умолчанию; одинаковые имена/пути дают ошибку. Scene, полный
   path и instance ID — совместные ограничения, не альтернативный fallback.
   Component ID не равен GameObject ID; после restart/load перечислить заново.
4. Снять A, изменить **один** фактор обратимо, снять B и затем A′. Проверить
   фактическое значение и положительный контроль стимула, а не только `ok`.
5. Вернуть preimages, прочитать diff и итоговые camera/player/UI-состояния.
   Ошибка восстановления остаётся открытым результатом, не «cleanup done».

Read-only старт из PowerShell:

```powershell
Invoke-RestMethod 'http://127.0.0.1:28777/state'
Invoke-RestMethod 'http://127.0.0.1:28777/render/snapshot?limit=8'
```

Для устойчивого артефакта использовать MCP
`screenshot_frame(retain=true, label="...")`: PNG, SHA256 и metadata копируются
вне окна автоматического удаления 40 игровых снимков. Сравнивать только кадры
одного capture pipeline с одинаковыми размерами; не ресайзить ради diff.

## 3. Кадры и временные эффекты

- Обычный `/screenshot` не включает overlay Canvas. Для окуляра нужен
  **frame** или нативная запись с видимым UI.
- До приёмки проверить GPU/API, разрешение и число ненулевых RGB-пикселей.
  В этой установке переход игры на AMD iGPU давал полностью чёрный композит,
  даже при живой игре/телеметрии. `black-frame` не считается чистым кадром.
  Не менять GPU/погоду/достижения без разрешения автора ради получения картинки.
- Конфигурация камеры — не GPU submission. «Камера enabled», RT существует
  или heartbeat идёт — недостаточно для доказательства рендера.
- Для цветового A/B — пауза и одинаковый пресет. Для движения/первого кадра
  нужна запись без паузы: пауза скрывает temporal-дефект и останавливает часть
  опроса крутилок. На 30-fps записи один игровой кадр при ~60 fps может выпасть.
- Центр/радиус окуляра брать из текущего layout, uiScale и разрешения, не из
  центроида ярких облаков. Усреднение по всей апертуре может скрыть асимметрию
  и смаз одной половины; выбирать метрику под симптом и проверять нативную вырезку.

## 4. Камеры секстанта: действующие инварианты

Подробности — [CAMERA_GUIDE.md](CAMERA_GUIDE.md), доказательства —
[SEXTANT_PLAN.md](../SEXTANT_PLAN.md) §16.23–16.25.

| Проверка | Действующее правило / подтверждённый результат |
|---|---|
| Путь PIP | attached **либо** standalone fallback; `RadioNav.PipSingleRender=1` default. `0` — диагностический старый двойной путь |
| Интерьер | `RefreshMirroredState(viewCamera)` → `InteriorMirror.Sync(insideBoat)`; внутри root имеет `RenderScene=true` и полный `(0,0,1,1)` culling rect |
| Экстерьер | живой `RenderScene`/rect основного вида зеркалится обеим PIP; интерьерный override снаружи не применяется |
| Поза | обе ветки в одном parent frame; правая сохраняет pitch дуги. Позиция — от игровой InteriorCamera, не от зависимого мод-клона |
| История на open-edge | обе PIP: `PostProcessLayer.ResetHistory()` + reset-флаг; main не сбрасывается этим фронтом |
| Лампа | причинный GPU A/B/A′: PIP **0→12→0**, main **1→1→1**; продуктовый capture и 12 checkpoints. Это draws общего меша, не число видимых ламп |
| Первый кадр | **24/24** записанных B-открытий на 30 fps чистые; 60-fps контроль сам по себе причинную связь не доказывает |

Не чинить лампу изменением pose, alidade, слоя света, шейдера или бандла:
её доказанный дефект был **culling до submission**. Историческая линия про
«светящуюся стенку луны» не объяснила наблюдавшийся смаз и не должна возобновляться
по одному похожему радиальному числу.

## 5. Ввод и игровые постусловия

- Key: Z → прочитать `/sextant` и проверить open; Escape → проверить меню.
  Click: координаты получать через `screen_point`, затем читать изменение UI.
  Drag: проверять нормализованную позицию/значение и возвращать preimage.
- uGUI drag не является drag 3D-карты; для картографии использовать `/map/*`
  и проверять реальные точки/линии. Маркеры RadioNav — родные `MapPointUI`.
- `SendInput` с нулём вставленных событий — **заблокированный стимул**, не
  отрицательный тест. `/camera/fly` переводит в FreeFly, где секстант не работает;
  неподвижные снимки этого режима не доказывают исправление PIP.
- Телеметрия пробы должна подтвердить движение. `ProbeRun` — счётчик запуска,
  его увеличивают; `ProbeSpinRate` — десятые °/с. Путь пробы отключает StabLock,
  поэтому не покрывает все пути обычной мыши. Проверять реальные settings после
  применения; для части крутилок нужно переоткрытие прибора.
- `player_jump`/warp — перенос, не проход через люк. Даже успешная инициация
  остаётся `verified=false`. Читать player: camera mode, impersonation,
  compartment/slot, `insideBoat`, `inTransition`; положение само по себе не
  гарантирует согласованность камерного состояния.

**Открыто:** обычный проход через люк с подтверждённой сменой insideBoat;
внешняя эстетическая приёмка звёзд/PSF на чистом небе. Эти пункты не закрыты
приёмкой лампы, UI-ввода или snapshot-конфигурации.

## 6. Восстановление временных настроек

`with_settings` сохраняет типизированные preimages **до первой записи**, держит
lease с TTL и блокирует конфликтующие leases. Нельзя включить отсутствующий
prefs-ключ таким способом: потребовалось бы удалить его при rollback. Создание
ключа — отдельное явно разрешённое действие. Leases не блокируют произвольные
прямые записи или изменения самой игрой.

- TTL-worker и EOF пытаются восстановить; неудачные inverses остаются held и
  повторяются. Hard kill не означает, что восстановление уже состоялось.
- Из нового адаптера читать `with_settings_status`, затем при необходимости
  `with_settings_recover(journal, token)`. Авторитетен исходный журнал, не копия.
  Чужой активный owner и сменившийся PID **или** creation time игры запрещают
  recovery. Успешные inverses сохраняются по одному; неудачные остаются retryable.
- Default journal dir: `%LOCALAPPDATA%\Temp\opencode\uboat-mcp-leases`.
  Не удалять файл ради «чистого статуса»: сначала восстановить и прочитать diff.
  Commit намеренно оставляет новые значения и удаляет undo-данные.

## 7. Память и загруженная версия инструментов

`supermemory(mode:"help")` должен сообщать **загруженный**
`runtime.memoryDestinationVersion="origin-bound-v1"`, directory, tag и project ID.
Для RadioNavigation проверено: tag `radio-navigation`, ID `ae8090150b04e0d6`.
Хеш файла и `status=active` без runtime-help не доказывают, что bundle исполняется.

- Manual tools и recall следуют текущей директории. Отложенные captures и
  summaries сохраняют **исходный destination**, включая retry после переноса.
- Capture cadence **5**, `autoRecallEveryPrompt=false` в проверенной конфигурации.
  Транспортные отказы отложенных отправок покрыты runtime-регрессиями/мутациями,
  не принудительным отключением живого сервера. Старые смешанные записи не
  мигрировались и не удалялись; новое поведение не исправляет историю задним числом.
- Для reload сначала определить **подключённый** OpenChamber server URL/PID.
  `opencode service restart` может затронуть другую CLI-службу. V2-команда:
  `opencode api --server <connected-URL> post /api/location/reload`.
  Она пересоздаёт все загруженные locations и отменяет pending permissions/forms;
  согласовать с другой активной работой. После reload проверить каталог и help.
