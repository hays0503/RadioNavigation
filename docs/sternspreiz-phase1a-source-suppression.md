# Sternspreizglas — Phase 1a: супрессия актуального star-source

## Статус и границы

Живой результат 2026-09-27: scope-супрессия модового renderer `StarSkyRoot`
доказана per-PIP при нетронутом Main (проверки #1–2, #5, #7–8 PASS; #6 проходит
с ночной-Sun оговоркой). Проверки #3–4 — телеметрия PASS, но визуально
PARTIAL: PIP сохраняет родное небо, поэтому отсутствие модовых звёзд показано
счётчиками/средними, а не изолированным визуальным удалением звёзд. Эта фаза
доказывает только изоляцию — не перерисовку-без-подлога, не исключение TOD
Sun, не оптику PSF.

Mode 3 реализован как opt-in **диагностический кандидат** (живая проверка
scope супрессии выше; визуальное отсутствие звёзд остаётся partial). Это не
PSF, не renderer и не решение о замене изображения.
`RadioNav.SternspreizProbe` по умолчанию остаётся OFF.

Mode 3 намеренно узкий:

- Резолвить существующий `MeshRenderer` объекта `StarSkyRoot`; меш не
  клонировать и не перестраивать.
- Регистрировать этот renderer только на левую и правую PIP-камеры секстанта.
- Отключать его в существующем префиксе DeepPipeline-камеры, требовать в
  `IOpaqueImageEffect` доказательство супрессии того же кадра, затем копировать
  source в destination без изменений. Финализатор Harmony восстанавливает
  renderer.
- В mode 3 прятать renderer disposable фикстуры. Не выдавать `DrawMesh`, не
  сворачивать изображение, не применять шейдер, не трогать небесные объекты.
- Снимать регистрацию цели при возврате preference в 0 и при закрытии
  секстанта или уничтожении его PIP-фабрики. Main Camera никогда не
  регистрируется и не модифицируется. Нативное TOD Sun не выбирается и не
  обрабатывается.

Пути реализации:

- `Source/UI/SternspreizPipProbeEffect.cs` — mode 3 и pass-through колбэк
  доказательства (`sourceSuppressed`, кадр, валидность цели).
- `Source/UI/SextantPipFactory.cs` — выбор цели, регистрация обоих глаз,
  прятание фикстуры и OFF/close очистка.
- `Source/Logic/SternspreizPipRenderScopePatch.cs` — scope
  disable/restore и телеметрия имени/ID renderer на глаз.
- `RadioNavigation.SourceCheck/SourceCheckTests.cs` — статический граничный
  контракт.

телеметрию кодового пути как визуальное доказательство. Работайте снаружи на
мостике/палубе, в ясную тёмную ночь, когда модовый звёздный меш видимо
заполнен; для сравнимых A/B-скриншотов ставьте мир на паузу, чтобы кадры камер

любой работы по замене изображения. Полное прохождение доказывает лишь, что
этот модовый star renderer можно подавлять per-PIP при нетронутом Main. Оно
**не** доказывает, что результирующий кадр можно перерисовать без подлога,
что TOD Sun исключён или что равномерная-линия PSF оптически точна. Это
остаётся отдельными гейтами; ни шейдер, ни production renderer этой фазой не

## Офлайн-верификация

`Sternspreiz_Phase0IsProbeOnlyAndPipRouted` теперь фиксирует, что mode 3
выбирает существующий renderer `StarSkyRoot` для обоих PIP, никогда не
диспетчит sentinel-отрисовку, верифицирует супрессию текущего кадра, сообщает
ID/имя выбранного renderer и снимает регистрацию на OFF/close/teardown. Дополнительно
запрещает celestial-токены (`TOD_`, `SunDisc`, `MoonDisc`, `PlanetRenderer`,
`ConstellationMesh`) в probe-эффекте и render scope.
`Sternspreiz_Phase1MathRemainsPureAndOffline` запрещает runtime-ссылки на тип
математики, включая `ConvolveHorizontalField`. Это статические контракты, а не
живая приёмка выше.
